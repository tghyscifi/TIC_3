# generator 工具包 学习指引（面向 onnx2prim）

> **定位**：`generator/` 下有 40+ 个模块、上万行代码，本文**只挑你在做 `onnx2prim` 时真正需要的那部分**。不追求覆盖全，追求"读完就知道该动哪里、不该动哪里"。
> **前置**：先读完 [LeNet/手写映射学习指引.md](LeNet/手写映射学习指引.md)。那份讲"手写映射每一步在做什么"，这份讲"每一步用到的工具在哪个文件里"。
> **本文所有路径**相对于工程根目录 `tianjic_x1_software_0814/`。

## 导语：这个包在整条链路里的位置

```
你的 codegen 产物（Python 源码）
    │
    │  exec() → gen_*_map_config() → map_config 嵌套字典
    ▼
┌─────────────────────────── generator 工具包 ───────────────────────────┐
│                                                                        │
│  ① 组装与检查            mapping_utils/map_config_gen.py               │
│     MapConfigGen.add_config / add_router_info / add_prim_at_the_beginning│
│                                                                        │
│  ② 字典 → 对象           code_generator/map_config.py                  │
│     MapConfig / GroupConfig                                           │
│                                                                        │
│  ③ 建内存 + 跑行为仿真    behavior_simulator/          ← 纯 Python 仿真器 │
│     Simulator.map() / .simulate()  →  chip_array.config_json_output()  │
│                                                                        │
│  ④ 对象 → JSON           code_generator/primitive_json.py              │
│     每个原语类 → PI_parameter 的 {PIC:6, ...} 字段                      │
│                                                                        │
│  ⑤ 入口与对拍            test_engine/test_engine.py                    │
│     TestEngine.run_test()                                             │
└────────────────────────────────────────────────────────────────────────┘
    │                          │
    │ dump JSON                │ 同时跑硬件仿真器
    ▼                          ▼
json_config_*.json      TianjicX1_SIM.exe
                           │
                           └─→ 两个仿真器的输出逐文件对比
```

**最重要的一个发现：这个工程有两个独立的仿真器。**

| 仿真器 | 是什么 | 在哪 | 你怎么用 |
|---|---|---|---|
| **行为仿真器** | 纯 Python 的芯片行为模型 | `generator/behavior_simulator/` | `TestEngine` 会先跑它，产出 Python 侧输出 |
| **硬件仿真器** | `TianjicX1_SIM.exe`（Verilog） | `simulator/` | `TestEngine` 再调它，然后逐文件对比两边 |

`TestEngine.run_test()`（[test_engine/test_engine.py:24-43](test_engine/test_engine.py#L24-L43)）的流程是：`Simulator.map()` 建结构 → `Simulator.simulate()` 跑 Python 仿真并产出 JSON → 把 JSON 落盘 → 调 `.exe` → `compare_cmp_out_dir_result()` 比对两边输出。

> **这对你的意义**：你可以在**完全不碰 `.exe`** 的情况下调试映射逻辑。而且注意 [test_engine.py:39-43](test_engine/test_engine.py#L39-L43)——非 Windows 平台会直接 `return True` 跳过硬件仿真。也就是说在 Linux/Mac 上跑 `run_test()` 只跑 Python 行为仿真。**这是你迭代 codegen 的最快反馈环。**

## 第一层：必须精通的三件套

这三件是 `codegen` 直接生成代码去调用的东西。**不懂它们写不出正确的 codegen。**

### 1.1 [mapping_utils/prims.py](mapping_utils/prims.py)（778 行）—— 原语工厂

13 个工厂函数，每个负责"填一个原语类的所有寄存器字段"。这是 codegen 的输出目标。

| 工厂 | 建的对象 | PIC | 用途 |
|---|---|---|---|
| `p02` | `Prim_02_Axon` | 0x02 | 平均池化（X1+X2） |
| `p03` | `Prim_03_Axon` | 0x03 | 张量乘（X1×X2） |
| `p04` | `Prim_04_Axon` | 0x04 | MLP |
| `p06` | `Prim_06_move_merge` | 0x06 | 数据搬运/合并 |
| `p26` | `Prim_06_move_split` | 0x06 | 数据搬运/拆分 |
| `pX5` | `Prim_X5_Soma` | 0x05 | 池化 + 比较 |
| `p07` | `Prim_07_LUT` | 0x07 | 查找表（激活函数） |
| `p08` | `Prim_08_lif` | 0x08 | **LIF 神经元（SNN 的关键）** |
| `p09` | `Prim_09_Router` | 0x09 | 路由器 |
| `p41` | `Prim_41_Axon` | 0x41 | 卷积（CNN0） |
| `p43` | `Prim_43_Axon` | 0x43 | aX+Bias |
| `p81` | `Prim_81_Axon` | 0x81 | 卷积（CNN1） |
| `p83` | `Prim_83_Axon` | 0x83 | aX+Bias |

**你要从这份文件里提取什么**：每个工厂的参数名 → 对应哪个寄存器字段（例如 `addr_ina` → `axon.Addr_InA_base`）。codegen 的参数命名应当**直接沿用这些名字**，否则没法复用。

**要注意的坑**：`p09` 的 docstring 写着"需要手动添加路由表"——它只填了寄存器，路由表要额外调用 `router.addRHead(...)`。codegen 必须同时生成这两部分。

### 1.2 [mapping_utils/map_config_gen.py](mapping_utils/map_config_gen.py)（479 行）—— 组装器

`MapConfigGen` 是你产物的第一道消费者。**你要用的 5 个方法**：

| 方法 | 干什么 | 你的 codegen 里对应哪一步 |
|---|---|---|
| `add_config(map_config, core_offset=(x,y))` | 把一组 map_config 合并进总配置；**所有 core 坐标加 offset**；并给这组分配新的 phase_group 编号 | ⑩ 组装 |
| `add_router_info(map_config)` | 把每个 `addRHead` 的**相对坐标 (X, Y)** 解析成实际目标核（含跨芯片回绕） | ⑨ 路由表 |
| `add_prim_at_the_beginning(map_config, prim)` | 给**所有** core 在开头插入一个 phase（LeNet 用它插 phase 0 的初始搬运原语） | ⑦ 排 phase |
| `get_router_rhead_base(prims, index=-1, ...)` | 算出下一个可用的 RHead 基地址（默认 0x300，上限 0x400） | ⑨ 路由表 |
| `conut_prim_number(map_config)` | 统计每个 core 的原语总数，返回最大值 | 校验（但没人调用它） |

`gen_dict` 是个 property：返回 `deepcopy + add_router_info` 后的完整配置，方便一次拿到成品。

> ⚠️ **必须纠正的一个误会**：`MapConfigGen.check(map_config)` 是**空函数**（[map_config_gen.py:376-377](mapping_utils/map_config_gen.py#L376-L377)），旁边还有个同样空的 `_check_static_prim_end_addr()`。
>
> 也就是说：**这个工程没有任何静态校验。** 地址是否重叠、是否越界、对齐是否正确、原语数是否超限、RHead 是否溢出——**全靠仿真跑一遍才知道**。
>
> 我在上一份指引的对话里曾把 `MapConfigGen.check` 当成校验工具提过，那是错的。这条对你反而是好消息：**写一个真正的 `validate.py` 是 `onnx2prim` 里投入产出比最高的一个模块**，因为现在完全空白。

### 1.3 [mapping_utils/data_handler.py](mapping_utils/data_handler.py)（179 行）—— 数据布局

核心是 `tensor_split`（详见 LeNet 指引的站 3）。另外三个：

| 方法 | 用途 | 你需不需要 |
|---|---|---|
| `tensor_split(raw_data, split_dict, data_type, alignment, dims, is_weight)` | 张量 → 硬件内存布局 | **必用**，第四次用到 |
| `lut_gen(func, max_abs_float_input, input_width, input_q_factor, output_width, output_q_factor, signed)` | 生成激活函数查找表 | SNN/非线性激活才需要 |
| `check_model(model)` | 校验权重/偏置能否被 int8/int32 精确表示 | 在量化检查里可复用 |

## 第二层：必须理解接口、但不需要改的四个模块

### 2.1 [code_generator/](code_generator/)（3 个文件，866 行）

| 文件 | 内容 | 你需要知道什么 |
|---|---|---|
| `map_config.py`（121 行） | `MapConfig` / `GroupConfig` —— 把嵌套字典包装成对象 | `GroupConfig.get_prim_list(core_id, prim_name, index)` **同时支持两种 prim 形态**：`{'axon': x}` 字典形式，或 `[axon, soma1, router, soma2]` 列表形式（[map_config.py:39-56](code_generator/map_config.py#L39-L56)）。你的 codegen 用哪种都行，但要保持一致 |
| `primitive_json.py`（744 行） | 每个原语 → `PI_parameter` 的 `{PIC:6, ...}` 字典 | **不用读实现**，但要看它的 `set_primitive_json` dispatch 表（[primitive_json.py:11-45](code_generator/primitive_json.py#L11-L45)）——**那就是硬件支持的原语全集**，你的 codegen 不能超出这 13 种 |
| `map_strategy_parser.py`（**1 行**） | 空壳，只有两行注释"解析文本格式的映射策略" | **这个空文件就是给你留的坑位。** 原作者的意图显然是：将来有人把"映射策略"写成文本/IR，由它解析成 code_generator 的输入结构。你的 `onnx2prim` 本质上就是填这个坑 |

`GroupConfig` 里还有两个可能被你忽略的字段：`clock0_in_step` / `clock1_in_step`（多 step 时的时钟），以及 `get_instant_pi_list` / `instant_prims`（即时原语）。LeNet 不用，多 step 场景要用。

### 2.2 [behavior_simulator/](behavior_simulator/)（~2200 行）—— 纯 Python 行为仿真器

| 文件 | 行数 | 干什么 |
|---|---|---|
| `chip_array.py` | 51 | 芯片数组容器；`config_json_output()` 产出顶层 JSON（`sim_clock` + `ChipArray`） |
| `chip.py` | 304 | 单个芯片：core 管理、phase clock、trigger clock、step 执行次数 |
| `core.py` | 492 | 单个核：PI group 列表、内存、`config_json_output()` 产出 `CoreInfo`/`PI`/`initData`/`MemoryOutput` |
| `PI_group.py` | 241 | 一个 phase 的原语四元组 |
| `memory.py` | 899 | 内存行为模型（最大的一块） |
| `execution/` | — | 执行流程、core 状态、锁 |
| `router/` | — | 路由行为模型 |

**你要读的只有 [simulator.py](behavior_simulator/simulator.py)（235 行）**，因为 `map()` 里的 `_add_PI_groups` / `_init_memory` / `_add_phase_output_print` 定义了**原语对象 → 内存初始化 + 输出打印**的规则：

- `_init_memory`：遍历每个原语的 `memory_blocks`，调 `core.init_memory(name, start, length, data)`。**这说明"权重怎么进内存"完全取决于原语对象的 `memory_blocks`，而 `memory_blocks` 是原语构造函数里由 `data_w=` / `data_b=` 生成的**——这就是 `lenet_data.py` 里的 `tensor_split` 结果的最终去向。
- `_add_phase_output_print`：决定每个 phase 打印哪些内存片段到输出文件。**它顺带揭示了各原语的地址字段语义**（例如 `router` 是 `0x8000 + Addr_Din_base`，印证了 LeNet 指引里"p09 用 Mem2 相对地址"的说法）。

`simulator.py` 里还有两个值得注意的限制：`# FIXME 只支持3*3阵列`（[:45](behavior_simulator/simulator.py#L45)，硬编码 4×4 循环）和 `if (0, 0) not in self._chip_array`（[:29](behavior_simulator/simulator.py#L29)，硬编码单芯片 (0,0)）。多芯片支持是不完整的。

### 2.4 [primitive/](../primitive/)（13 个原语类）

**这是硬件行为的最终依据，也是你查"这个参数到底什么意思"的地方。**

每个原语类的结构：
```
Prim_XX_xxx.py
  ├── __init__        寄存器字段默认值（= 参数含义的清单）
  ├── __str__         名字（但注意 Prim_X5_Soma 的__str__是错的，见 LeNet 指引陷阱 2）
  ├── cal_para()      从输入形状推导内部量（Py_real/Px_real/nix_wr_real 等）
  ├── init_data()     生成 memory_blocks（调用 data_generator 造随机数据，或接入你传的 data_w/data_b）
  └── 计算/校验方法    （行为模型或寄存器打包）
```

**你应该建立的用法**：当你不确定某个参数的意义时，去对应原语类的 `__init__` 看它的字段默认值和注释。例如 `Prim_41_Axon.__init__` 里 `InA_type = 1  # 可配置更改：[00]int32[01]int8[10]uint8 [11]Tenary` —— 这一行注释解释了整个地址/位宽体系。

## 五个你必须背下来的 API

```python
# 1. 造原语
from generator.mapping_utils.prims import p41, p81, pX5, p06, p09, p08
axon = p41(px=12, py=12, cin=6, cout=16, kx=5, ky=5, sx=1, sy=1,
           addr_ina=0x0100, addr_inb=0x40E8, addr_bias=0x4598, addr_out=0x0410,
           pad_top=1, pad_down=1, pad_left=1, pad_right=1,
           ina_type=1, inb_type=1, load_bias=2,
           data_w=..., data_b=...)

# 2. 组装
config = MapConfigGen()
config.add_config(sub_map_config, core_offset=(0, 0))
MapConfigGen.add_router_info(config.map_config)      # 或直接用 config.gen_dict
MapConfigGen.add_prim_at_the_beginning(config.map_config, prim={...})
MapConfigGen.get_router_rhead_base(prims)

# 3. 布局
from generator.mapping_utils.data_handler import DataHandler
DataHandler.tensor_split(raw_data, split_dict, data_type, alignment, dims, is_weight)

# 4. 仿真
from generator.test_engine import TestMode, TestEngine
from generator.test_engine.test_config import HardwareDebugFileSwitch
tester = TestEngine(config.map_config, {
    'tb_name': 'MyCase',
    'test_mode': TestMode.MEMORY_STATE,
    'debug_file_switch': HardwareDebugFileSwitch().close_all.dict,
    'test_group_phase': [(0, 1)],
})
assert tester.run_test()

# 5. 逐地址对拍
from generator.mapping_utils.result_compare_with_clock_specific_simulator import \
    ResultCompareWithClockSpecificSimulator
compare = ResultCompareWithClockSpecificSimulator(
    data_file_name='MyCase', save_ref_data_en=True, phase_en=None)
compare.add_ref_data({phase: {(chip, core): [{'data': d, 'addr_start': a, 'type': t}]}})
compare.run(); compare.show_result()
```

## 三个"这个包里没有的东西"（= 你的工作量）

| 缺失 | 现状 | 为什么是你的活 |
|---|---|---|
| **静态校验** | `MapConfigGen.check()` 是 `pass` | 地址重叠/越界/对齐/原语数上限/RHead 溢出，全都只能靠仿真暴露。写 `validate.py` 是最高性价比的投入 |
| **策略解析/生成** | `map_strategy_parser.py` 只有 1 行 | 这就是 onnx2prim 要填的坑 |
| **多核自动切分** | 不存在。`plan_stages` 只按内存切，不按核切 | resnet50 的手写版是靠人肉把 28 核排出来的 |

外加一个半成品：多芯片支持（`behavior_simulator` 硬编码 `(0,0)`，`# FIXME 只支持3*3阵列`）。
