## 导语：手写映射在做什么 —— 从 `.pth` 到芯片

### 一句话概括

芯片不认识 `nn.Conv2d`。它只有**一堆可以配置寄存器的原语单元**，和**四块内存**。

所谓"手写映射"，就是人工完成一次翻译：把「一个训练好的网络的逐层前向计算」翻译成「每个核在每个时钟节拍上，四个原语单元各自读哪个地址、算什么东西、写哪个地址」。

翻译的产物是一个巨大的嵌套字典 `map_config`，它最终会被序列化成 JSON 喂给 `TianjicX1_SIM.exe`。

### 翻译过程中真正要回答的只有五个问题

| # | 问题 | 本质 |
|---|---|---|
| 1 | **这一拍的算术怎么表达？** | 一个卷积/池化/全连接，对应哪个原语的哪几个寄存器字段 |
| 2 | **数据放在哪、怎么摆？** | 张量在内存里的字节排布 + 每个张量分到哪段地址 |
| 3 | **谁在什么时候算？** | 多少个 phase，每个 phase 算哪一层 |
| 4 | **数据怎么流动？** | 层与层之间、核与核之间、芯片与 FPGA 之间怎么搬运 |
| 5 | **位宽怎么对上？** | float 权重和激活怎么变成 int8 乘加 + 定点截位，且不溢出 |

手写映射所有的代码，都是在这五个问题上做选择。下面按依赖顺序拆成十一步。

### 全景流水线

```
 ① 量化改造          模型里插入 Cut，权重→int8，偏置→int32
      ↓                 （lenet_model/lenet.py）
 ② 抓参照数据        跑一次推理，hook 抓下所有中间层输入输出
      ↓                 （lenet_model/lenet_data_handler.py）
 ③ 定 cut 表         每层截位位数 = log4(权重 scale)
      ↓                 （lenet_cut_config.py）
 ④ 张量布局          按硬件存储格式重排 + 对齐 → 逐位置的字节流
      ↓                 （lenet_data.py → data_handler.tensor_split）
 ⑤ 分配地址          Mem0 放激活、Mem1 放 CISO，逐个算出起止字地址
      ↓                 （散落在 g1_1core.py 的 addr_* 参数里：手写）
 ⑥ 分区             几个 phase_group？每组几个 core？core 摆在哪？
      ↓                 （__main__ 里的 add_config + core_offset）
 ⑦ 排 phase         phase 0 收发，phase 1..N 一层一拍
      ↓                 （phase_en 数组 + offset）
 ⑧ 选原语填寄存器    每 phase 每 core 一个 {axon, soma1, router, soma2}
      ↓                 （g0/g1/g2.py 里的 p41/p81/pX5/p06/p09 调用）
 ⑨ 写路由表          addRHead 声明相对目标，add_router_info 解析成实际核
      ↓                 （g0/g2.py + MapConfigGen.add_router_info）
 ⑩ 组装              add_config 平移坐标并分配 group 号，设时钟
      ↓                 （__main__）
 ⑪ 仿真与对拍        TestEngine 跑，拿②的参照数据逐 phase 逐地址比对
                        （lenet_check.py / batch_test_lenet.py）
```

### 十一步逐条说明

**① 量化改造** — 在 PyTorch 模型里，每个需要量化的算子**后面**插入一个 `Cut` 模块。`Cut.forward` 就是 `x.div(2**(2*cut)).floor().clamp()`，模拟硬件的右移截位。同时把权重乘 128、偏置乘 128² 后 round 成整数。这一步的意义是：**让 Python 端的数值和芯片端的数值完全一致**，否则后面无从对拍。

**② 抓参照数据** — 用 `register_forward_hook` 跑一次推理，把每一层的输入、输出都抓成 numpy 数组存起来。这批数据有两个用途：**初始化内存**（作为 `init_data` 喂给原语）和**作为正确答案**（仿真结果要和它一样）。

**③ 定 cut 表** — 每一层的输出激活要右移多少位。规则是 `cut = log4(权重 scale)`，其中权重 scale 是手填的经验值（256 / 1024）。这一步决定了定点乘加的结果能不能塞回 int8 而不失真，**是手写映射里最依赖经验、最少有代码依据的一环**。

**④ 张量布局** — 硬件内存不是行优先的 C 数组。`tensor_split` 干三件事：按指定的维度优先顺序重排、把每个维度向上对齐到指定粒度（权重/偏置通道对齐 32、激活对齐 16）、把 int8 按 4 个一包塞进 32 位字。**对齐会凭空放大内存占用，地址表里那些"多出来的零"就来自这里。**

**⑤ 分配地址** — 决定每个张量放在哪段地址。规则很简单但要算准：激活放 Mem0、权重偏置放 Mem1（放不下就借用 Mem0，LeNet 的 FC2 就是这种情况）、路由数据放 Mem2、FPGA 出口是 Mem3。**地址生命周期是一个 phase**——同一个 phase 内用完就可以被下一个 phase 覆盖，这就是为什么 `0x0100` 和 `0x0410` 会反复出现。

**⑥ 分区** — 决定用几个 phase_group。LeNet 用了三个：G0 数据源、G1 计算、G2 输出侧。然后用 `add_config(core_offset=...)` 把每组的 core 坐标整体平移，错开摆在同一张 16×10 网格上。

**⑦ 排 phase** — 把计算切成串行的节拍。LeNet 是 `phase 0` 收发 + `phase 1..5` 五层，一共 6 拍。`phase_en` 数组控制每一拍是否使能。

**⑧ 选原语填寄存器** — **这一步是全部工作量所在。** 对每个 phase、每个 core，决定四个槽位放什么原语、每个参数填什么值。这就是 `g1_1core.py` 里那五个 `if phase_en[...]` 块在干的事。

**⑨ 写路由表** — 数据要跨核/跨组流动，就得声明路由。`addRHead(X=..., Y=...)` 用**相对坐标**描述"从现在这个核，往 X 列 Y 行送"。`add_router_info` 再把这些相对坐标解析成实际的目标核（含跨芯片回绕）。

**⑩ 组装** — 把三组的 map_config 合并，设定 `sim_clock`（总时钟数）和 `step_clock`（终止条件）。

**⑪ 仿真与对拍** — 跑 `TestEngine`，然后拿①-②产生的参照数据去比对仿真后的内存状态。**没有这一步，前面十步都是猜。**

## 一、先建立五个心智模型（读代码前必须有的框架）

### 1.1 层级结构

```
chip (0,0)
 └── phase_group 0 / 1 / 2      ← 由 add_config() 分配，本工程正好三组
      └── phase 0..N            ← 一次"全阵列同步节拍"，一拍算一层
           └── core (x,y)       ← 16×10 网格里的一个核
                └── prim 四元组  ← {'axon','soma1','router','soma2'}
```

**这是最重要的一句话：一个 phase = 一拍 = 一层。** [g1_1core.py:63-147](g1_1core.py#L63-L147) 里五个 `if phase_en[offset + k]` 块，就是五层，`offset=1` 是因为 phase 0 被留给数据收发。

### 1.2 四个原语槽位对应四个物理单元

| 槽位 | 单元 | 干什么 | LeNet 里谁来用 |
|---|---|---|---|
| `axon` | A | 卷积/全连接的乘加阵列（权重 × 激活 → 部分和） | `p81`（conv1）、`p41`（其余） |
| `soma1` | S1 | 池化 + 截位（Cut）；或投票比较 | `pX5` |
| `router` | R | 跨核/跨组搬运数据包 | 只在 phase 0 用 `p09` |
| `soma2` | S2 | 把收到的数据搬进计算内存 | 只在 phase 0 用 `p06` |

一层的计算只需要 `axon` + `soma1` 两个；`router`/`soma2` 留给收发 phase。这就是为什么 [g1_1core.py](g1_1core.py) 里每个计算 phase 后面都跟着 `router = None; soma2 = None`。

### 1.3 字地址，不是字节地址

芯片内部 32 位寻址。代码里写 `0x1040 >> 2` 是**从字节地址换算成字地址**（见 [../lenet.py:778](../lenet.py#L778)）。四块内存（字地址）：

| 内存 | 大小 | 字地址范围 | 存放内容 |
|---|---|---|---|
| Mem0 | 64KB | `0x0000 ~ 0x3FFF` | 激活（输入/中间结果）+ FC2 的权重偏置 |
| Mem1 | 64KB | `0x4000 ~ 0x7FFF` | CISO：权重和偏置（除 FC2） |
| Mem2 | 16KB | `0x8000 ~ 0x8FFF` | 路由用：PI_B `0x8000-0x82FF`、R_lab `0x8300-0x83FF`、R_IO `0x8400-0x8FFF` |
| Mem3 | 16B | `0x9000 ~ 0x9003` | 送 FPGA 的输出口 |

> ⚠️ `Prim_06` / `Prim_X5` 里有一行 `mem_sel = 1 if addr_out == 0x9000 else 0` —— **`0x9000` 是个哨兵值，不是普通地址**，看到它就知道这一步在往 FPGA 输出口写。

### 1.4 量化约定

- 激活：int8；权重：int8（量化时乘 128 后 round）；偏置：int32（乘 128² 后 round），见 [lenet_model/lenet_data_handler.py:31-37](lenet_model/lenet_data_handler.py#L31-L37)
- 截位在硬件上叫 **Cut**：`x >> (2 * in_cut_start)`，见 [lenet_model/lenet.py:57](lenet_model/lenet.py#L57)（`x.div(2**(2*in_cut_start)).floor()`）
- cut 值来自手写经验表 `weight_parameters`，取 `cut = log4(scale)`：

| 层 | weight scale | cut | 名字 |
|---|---|---|---|
| conv1 | 256 | 4 | `cut1` |
| conv2 | 256 | 4 | `cut2` |
| fc1 | 1024 | 5 | `fc_cut1` |
| fc2 | 256 | 4 | `fc_cut2` |
| fc3 | 256×4 = 1024 | 5 | `fc_cut3` |

`DataHandler.check_model` **只校验权重/偏置能否被 int8/int32 精确表示**（[../mapping_utils/data_handler.py:144-151](../mapping_utils/data_handler.py#L144-L151)），它不推导 cut。cut 是人工经验值。

### 1.5 权重不是"推理图"的一部分，而是铺进内存的初始数据

硬件没有 `nn.Conv2d` 对象。权重/偏置通过 `tensor_split` 按硬件布局重排成嵌套 list，作为 `data_w=` / `data_b=` 传给原语构造函数，由 `init_data()` 变成 `memory_blocks` 初始化内存。

## 二、阅读路线（五站，每站一个产出）

### 站 1 — [lenet_cut_config.py](lenet_cut_config.py)（36 行，5 分钟）

唯一的产出：记住 `QuantizationConfig['cut1'] = 4` 这套名字。这些名字**必须和网络模型里 Cut 模块的模块名逐字一致**，因为 [lenet_data_handler.py:40-43](lenet_model/lenet_data_handler.py#L40-L43) 是拿 `named_modules()` 的名字去查表的。

### 站 2 — [lenet_model/lenet.py](lenet_model/lenet.py) + [lenet_data_handler.py](lenet_model/lenet_data_handler.py)（~240 行）

**读法：不要逐行读 `forward`，只抓三件事。**

1. `Cut` 放在哪 —— 每个需要量化的算子**后面**都跟一个 `Cut`。注意 `forward` 里 `cut1 → relu1 → max_pool1` 的顺序：**Cut 在 ReLU 和 MaxPool 之前**。
2. `LeNetDataHandler.__init__` 的 hook 机制（[:52-68](lenet_model/lenet_data_handler.py#L52-L68)）：注册 forward hook 跑一次推理，把所有中间层的 input/output 抓成 numpy，存进 `self.__internal`。**这就是"参照数据"的来源** —— 后面既用来初始化内存，也用来和仿真结果对拍。
3. `parameters` 这个属性名的实际含义：它不是"参数"，是 `{模块名: {'input':…, 'output':…, 'weight':…, 'bias':…}}` 的字典。

产出：你能说出 `handler.parameters['conv1']['output']` 是什么（conv1 的输出激活，量化后的 int8）。

### 站 3 — [lenet_data.py](lenet_data.py)（104 行）

**这一站最容易被跳过，但它决定了地址空间。** 读法：对着 `tensor_split` 的参数逐个问"为什么是这个数"。

`tensor_split(raw_data, split_dict, data_type, alignment, dims, is_weight)`（[../mapping_utils/data_handler.py:19-92](../mapping_utils/data_handler.py#L19-L92)）：

| 参数 | 含义 | 读代码时注意 |
|---|---|---|
| `data_type` | 0=int32（每个元素占 1 个字，successive_length=1）；1=int8（4 个打包进 1 个字，successive_length=4） | 这直接决定占多少字 |
| `alignment` | 每个维度向上对齐的粒度 | 通道维度一律对齐到 32（权重/偏置）/ 16（激活） |
| `dims` | 存储时的维度优先顺序 | weight 用 `(0,3,2,1)` / `(0,1,3,2)`，激活用 `(0,2,1)` |
| `is_weight` | 权重还要按 cout 的 32 分组分别 `ravel(order='F')` | 见 [:75-79](../mapping_utils/data_handler.py#L75-L79) |

### 站 4 — [g1_1core.py](g1_1core.py)（229 行，重头戏）

**这是整个手写映射的核心。建议读三遍。**

- **第一遍**：只看骨架。[:18-31](g1_1core.py#L18-L31) 建空 map_config 和 core 网格，[:34-59](g1_1core.py#L34-L59) 是 phase 0 收发，[:60-147](g1_1core.py#L60-L147) 是五个计算 phase，[:149](g1_1core.py#L149) 返回。
- **第二遍**：只填第三站的地址表（第三节的表 A），把每个 `p41(...)` 的 `addr_ina/addr_inb/addr_bias/addr_out` 和 `pX5(...)` 的 `addr_in/addr_out` 抄进去，转换成字地址。
- **第三遍**：只看 `pX5` 的 `cin` —— 有一条干净的规律，**可以用它自检你对硬件的理解**：

> `pX5.cin = ceil(上一层 cout / 32) * 32`
> conv1: ceil(6/32)*32 = 32 ✓　conv2: ceil(16/32)*32 = 32 ✓　fc1: ceil(120/32)*32 = 128 ✓　fc2: 96 ✓　fc3: 32 ✓

五个全部命中。`cout` 就是真实通道数，`cin` 是对齐后的读入通道数。

**自查点**：`pX5` 的 `type_in=0, type_out=1` —— 输入 int32（axon 的 V 区是 int32 部分和），输出 int8（截位后的激活）。这一条解释了为什么每层的 `addr_out`（V 区）和上一个 `pX5` 的 `addr_out` 能复用同一段地址。

### 站 5 — [g0.py](g0.py) + [g2.py](g2.py) + `__main__` + [lenet_check.py](lenet_check.py)

三组的角色：

| 组 | 位置 | 角色 | phase 0 关键词 |
|---|---|---|---|
| G0 | core (1,0) | 数据源 | `soma1` 从 Mem0 读图 → Mem3；router `addRHead(X=-1, Y=0)` → 发给 G1 |
| G1 | core (0,0) | 计算主体 | `soma2` 从 Mem2 `0x8380` 收图 → Mem0 `0x0000`；router `addRHead(X=0, Y=1)` → 发给 G2；`soma1` 把 fc_cut3 读到 Mem3 送 FPGA |
| G2 | core (0,1) 起 8 核 | 输出侧 | 8 个核链式接力（`core_x != 7` 用 `addRHead(X=1, Y=0)` 传给下一个核，`core_x == 7` 用 `Y=-128` 送 FPGA） |

`config.add_config(config_k, core_offset=...)` 把每组的 core 坐标整体平移（[../mapping_utils/map_config_gen.py:36-64](../mapping_utils/map_config_gen.py#L36-L64)），并分配新的 phase_group 编号；`add_router_info` 负责把 `addRHead` 的相对坐标 `(X, Y)` 解析成实际的目标核（含跨芯片回绕，见 `_get_real_core_idx`）。

**验证工具**：`lenet_check.py` 用 `ResultCompareWithClockSpecificSimulator` 把仿真后的内存状态和你喂进去的参照数据按 phase、按地址逐项比对（[lenet_check.py:20-73](lenet_check.py#L20-L73)）。它是"改了一行代码对不对"的最快反馈环。

## 三、速查表 A：五个计算 phase（全部换算成字地址）

| phase | 计算 | axon | 输入 A / 权重 B / 偏置 | axon 输出 V | soma1 | pX5 输出 | cut |
|---|---|---|---|---|---|---|---|
| 1 | conv1 1→6, 28² | `p81` k=5 s=1 | `0x0000` / `0x4000` / `0x40C8` | `0x0410` | `pX5` maxpool 2×2 | `0x0100` (12×12×6) | 4 |
| 2 | conv2 6→16, pad1, 12² | `p41` k=5 s=1 | `0x0100` / `0x40E8` / `0x4598` | `0x0410` | `pX5` maxpool 2×2 | `0x0690` (5×5×16) | 4 |
| 3 | fc1 400→120 | `p41` k=1 | `0x0690` / `0x45B8` / `0x77B8` | `0x0100` | `pX5` k=1 | `0x0400` (120) | 5 |
| 4 | fc2 120→84 | `p41` k=1 | `0x0400` / `0x2000` / `0x2B40` | `0x0100` | `pX5` k=1 | `0x0180` (84) | 4 |
| 5 | fc3 84→10 | `p41` k=1 | `0x0180` / `0x7838` / `0x7AD8` | `0x0400` | `pX5` k=1, `cmp_c=0x80808080` | `0x0800` (10) | 5 |

**注意 `0x0410` 和 `0x0100` 被反复复用** —— phase 1 的 pX5 输出（`0x0100`）在 phase 3 又被拿来当 axon 的 V 区。这是有意的地址复用：激活的生命周期是一个 phase，那个 phase 读完就释放。

## 五、速查表 C：五个原语

| 原语 | PIC | 一句话 | LeNet 里的关键参数 |
|---|---|---|---|
| `p81` | 0x81 | 卷积 axon（CNN1 模式，权重按 **16** 一组分块） | `cin/cout/kx/ky/sx/sy`, `addr_ina/inb/bias/out`, `load_bias=2` |
| `p41` | 0x41 | 卷积 axon（CNN0 模式，权重按 **64** 一组分块；多出 `axon_delay`/`L4_num`/`L5_num`） | 同 p81，另加 `pad_*` |
| `pX5` | 0x05 | 池化 + 截位二合一（`PIC_Mode=0` 为 max） | `cin`（对齐后）, `kx/ky/sx/sy`, `cmp_c`, `in_cut_start`, `type_in/out` |
| `p06` | 0x06 | 数据搬运/合并 | `length_in/num_in`, `length_out/num_out`, `addr_ciso`, `type_in/out` |
| `p09` | 0x09 | 路由器（**路由表要手动 `addRHead`**） | `send_en/receive_en`, `addr_din_base`, `addr_rhead_base` |

`p41` / `p81` 的差别只在分块粒度和 padding 处理（[../primitive/Prim_41_Axon_CNN0_new.py](../primitive/Prim_41_Axon_CNN0_new.py) vs [../primitive/Prim_81_Axon_CNN1_new.py](../primitive/Prim_81_Axon_CNN1_new.py)）——LeNet 里 conv1 用 `p81` 而其余用 `p41`，**更像是历史遗留而不是必须**。这一点值得自己去两个文件里确认。

## 七、陷阱清单

1. **[../lenet.py](../lenet.py) 里那段地址注释不可信。** 第 782 行有一段 `import argparse` 被误嵌进了三引号字符串里，把注释块从中间截断；而且 Mem0 部分地址基本都差 4 倍，还漏了整个 FC2。**地址一律从 `g1_1core.py` 的代码重建。**
2. **`Prim_X5_Soma.__str__` 的池化模式映射和构造函数注释相反。** `Prim_X5_Soma.__init__` 注释写 `0x01是min`（即 0 是 max），`pX5()` 也是 `PIC_Mode = 0 if mode == 'max'`，但 `__str__` 里却是"PIC_Mode 真值 → max pooling"。**打印出来的名字不可信，以 `pX5(mode=...)` 的参数为准。**
3. **`p09` 的地址约定与 `p06`/`pX5`/`p41` 不同**：`addr_din_base=0x380` 是 Mem2 相对偏移（对应绝对 `0x8380`），而 `addr_dout_base=0x1000` 是"用 Mem2 R_IO 区"的哨兵值（见 `p09` 里 `Dout_Mem_sel` 的判定）。别把两套混着读。
4. **[batch_test_lenet.py](batch_test_lenet.py) 会用正则直接改写 [../lenet.py](../lenet.py) 源文件**（[:48-63](batch_test_lenet.py#L48-L63)），替换 `case_file_name` 和 `input_image_path`。跑之前先提交一次 git，跑完检查 `git diff`。
5. **`clock_in_phase = 20_0000` 与 `sim_clock = 10_0000`**：前者是单个 phase 的时钟数，后者是整个仿真的总时钟数。`step_clock` 里的 `(10_0000-1, 10_0000)` 是终止条件，不是循环次数。

## 八、三个递进练习

**练习 1（复述级）**：不看代码，把这五层的 `addr_ina / addr_inb / addr_bias / addr_out` 和 cut 值默写出来。对照表 A。

**练习 2（改动级）**：把 LeNet 的 conv1 从 6 通道改成 **20** 通道，推导出所有受影响的变化：Mem1 里 Conv1 权重/偏置的新大小、MaxPool1 输出张量变大后哪些地址要平移、`pX5` 的 `cin` 变成多少。

> **这个练习有个隐藏的教训**：如果改的是 6→8 通道，会发现**几乎所有地址都不用动**——因为 8 和 6 都向上对齐到 16/32。对齐既让很多改动"免费"，也让很多改动"昂贵"（20 通道时 MaxPool1 输出从 576 字涨到 1152 字，直接和 `0x0410` 的暂存区撞车）。**地址对齐是手写映射里最容易算错的地方。**

**练习 3（独立级）**：去掉 MaxPool2，或干脆去掉 conv2 只留 conv1，改出一份能跑通仿真并通过 [lenet_check.py](lenet_check.py) 对拍的新映射。

做完练习 3，你就真正具备了做 `onnx2prim` 的判断力 —— 因为那时候你已经亲手做过一遍 codegen 要做的事。
