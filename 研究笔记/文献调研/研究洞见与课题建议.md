# 研究洞见与课题建议

这是一份基于用户提供资料和本地源码的研究构想，不是已实现系统、已复现实验或全领域新颖性检索。已综合 10 份 PDF 逐篇笔记和 16 份参考文档的四个专题，整理完成于 2026-10-12。以下“建议/假设”均为综合推断；作者事实与页码可沿链接回到逐篇笔记和原文。图形、版本和未复现实验的限制保留在各笔记中。

## 核心判断

`onnx2prim` 更适合定位为：**面向 Tianjic X1、保留状态与时间语义、具备分层验证和资源合法性检查的自动原语映射后端**。

不是只做“文件格式转换”，也不必先把 ONNX→NIR→BIVM 全链条全部实现。P03 已有扩展 ONNX、量化、任务图、原语融合和验证；P10 已有多层 SNN 编译框架；P08 已有 NIR 到 CPU 部署的参考路线。直接重新实现相似前端仍有工程价值，但不能单独支撑学术新颖性。P03 明确不研究底层资源分配和代码生成，而 P05 又说明映射算法必须服从具体硬件，这正是本工程应优先补齐的边界。[P03，第31—34、101—105页](逐篇笔记/P03_跨范式高层次编译器.md)；[P05，第172—173页](逐篇笔记/P05_时空映射与协同设计.md)；[P08，第9、13页](逐篇笔记/P08_SNN_MLIR.md)；[P10，第8—14页](逐篇笔记/P10_BIVM.md)。

## 洞见一：SNN 编译的首要对象是状态转移，不是层名字

NIR 互操作实验已经出现同名 LIF 的更新顺序和脉冲延迟差异，循环网络会放大失配；X1 p08 规定了严格阈值比较、复位后泄漏、不应期和时间窗行为。于是“识别到 LIF→调用 p08”不是充分条件。[P02，第9、11页](逐篇笔记/P02_NIR.md)；[P07，第44—46页](逐篇笔记/P07_X1概要设计.md)。

建议前端生成一份可检查的语义契约：输入编码、逻辑时间步、状态变量、初值、更新顺序、比较边界、reset、泄漏、输出读出、样本边界。源模型没有明确提供的信息，应要求补充或报不支持；不能通过换成 NIR 自动恢复导出时丢失的信息。

对应的 IR 应区分参数、持久状态和瞬时激活。时间步、phase、step、硬件分块轮转分别建模，不使用一个含糊的 Loop 标签。[P03，第45、47—48、83页](逐篇笔记/P03_跨范式高层次编译器.md)；[P08，第7、9页](逐篇笔记/P08_SNN_MLIR.md)。

这不是“首次发现 SNN 需要状态”的创新；可能的增量是**针对 X1 建立可执行的映射条件、明确拒绝原因，并用反例证据证明错误融合会在哪一步产生分歧**。

## 洞见二：先建立可信验证链，再优化映射

P03 已将量化近似与映射等价分开，使用量化模型作转换器黄金参考；MLIR 的结构校验也不证明数值等价。本地工程则存在空比较器、文件筛选风险和 p08 时间窗静态疑点。[P03，第32、103—105页](逐篇笔记/P03_跨范式高层次编译器.md)；[P09，第7、17页](逐篇笔记/P09_MLIR.md)；[代码对照](代码对照与工程缺口.md)。

建议把验证分为四层：

| 对照 | 要证明/衡量什么 | 不足以替代它的指标 |
|---|---|---|
| 源框架→语义 IR 参考执行 | 导入保留模型结构、输入编码和状态更新 | 文件成功解析、shape 一致 |
| 浮点/连续模型→选定离散整数模型 | 离散化和量化的任务误差、状态及脉冲变化 | “仍能分类几个样本” |
| 整数参考→原语行为模型 | 在声明的精确子集内逐层、逐时间步一致 | 最终 argmax 相同、两个仿真器互相一致 |
| 行为模型→X1 可执行仿真器/实机 | 参数编码、调度、路由、实现一致性与实际性能 | 非 Windows 路径返回 True、设计峰值 |

第一批测试应很小：等于阈值及±1；连续亚阈值输入；负数移位；复位后泄漏；非零初值；时间窗开关；连续两样本；Cin 切分后正负部分和及 bias 只加一次。这些有手算和首次分歧定位的价值。

脉冲的二值格一致率可能被大量零格抬高；应同时报告事件 precision/recall、首次分歧时间、脉冲时刻/计数和膜电位误差。P08 的 92% 是输出格一致率，不是分类准确率；量化后净脉冲数相近，也不等于脉冲对齐。[P08，第11页表II](逐篇笔记/P08_SNN_MLIR.md)。

## 洞见三：资源优化要把布局、状态和通信放在同一个问题里

“权重 + 激活小于单核容量”只是初筛。X1 存在 bank/访问接口、PI、路由表、接收缓存和持久状态；切分又带来 halo、权重复制、32 位部分和及重排，调度重叠可能改变峰值内存。[P07，第17、20—22页](逐篇笔记/P07_X1概要设计.md)；[P05，第72—79页](逐篇笔记/P05_时空映射与协同设计.md)。

原语选择不是独立决定：0x41/0x81 改变填充和布局；布局影响 Flatten/FC 重排；跨核边影响包数和接收缓存；状态不能像瞬时激活一样随意复用。一个候选计划应一起描述逻辑块、有效/补齐形状、layout、bank/地址、活跃区间、状态所属时间步、归约顺序、发送/接收与完成条件。

P05 有明确反例：减少存储的循环方案可以因 MAC 利用率低而更慢；某些循环更需要硬件取址改造。因而先筛合法候选，再以校准的计算/通信/等待模型排序，不默认“更多折叠更好”。[P05，第97—98、133、172—173页](逐篇笔记/P05_时空映射与协同设计.md)；[P03，第102页](逐篇笔记/P03_跨范式高层次编译器.md)。

工程材料给出具体佐证：Detection 高度八分块实际重复 7 行；Sound Tracking 将 8 通道补成 16 通道，物理发送量随之翻倍，四 phase 的尾量还不同。这些不是原 ONNX shape 所能直接代表的线上成本。地址也必须标单位：行为存储使用 4B word，JSON 部分字段再按访问粒度右移；重复进行“byte→word”换算会造成错误。[E01，约束6/9](工程专题/E01_原语与接口.md)；[E03，D02/D14](工程专题/E03_切分与通信.md)。

## 洞见四：自动映射的出口应包含可核验的部署接口

旧 Tianjic 的混合系统已说明，事件与数值的转换、输入保持、使能信号、预处理和控制反馈不能仅靠 dtype Cast 表达；展开/折叠的资源账还要包含 buffer、复制和归约核。[P04，第13、15、23页](逐篇笔记/P04_混合Tianjic.md)；[P06，第19—23页](逐篇笔记/P06_统一Tianjic.md)。

对本工程，建议除了原语配置再输出“输入/输出部署清单”：逻辑张量轴、物理填充与打包、每 core 每 phase 字节量、发送包序列、末包标记、初始状态/参数装载、Trigger 与输出有效条件。主机/FPGA 承担的图像预处理不能暗中计入芯片原语能力。这样才能判定是“生成了一段配置”，还是已经闭合“实际数据如何进入、结果如何解码”的部署流程。

E02 提供了可直接做一致性检查的例子：LeNet 幻灯片的 32×32 输入与当前代码的 28×28 并非同版本；ResNet 输入 phase 括注包数和主字节数存在矛盾；输出 Y 标识又不同于物理核 Y 坐标。应让部署清单由同一映射 IR 派生，并自动检查数据长度/包数/标志位，不靠人工复制表格。[E02，D05/D13/D15](工程专题/E02_LeNet与输入输出.md)。

## 洞见五：扩展模型应按约束组合选用例，而不是按名字扩表

E04 的六份文档分别提供残差旁路保活、GRU 门控与状态交换、MLP 部分和归约、Depthwise 九次累加及多播等需求。NSM 则只给存储图，没有足够状态转移语义；LCP 和 AlexNet 示例有复制的路由人数标签。它们适合作为需求/反例库，而不是现成支持清单。[E04，各文件小节](工程专题/E04_扩展网络需求.md)。

建议先按“分支/归约、持久状态、布局变化、受限非线性、特殊切分与通信”分类设计小用例，再选完整模型验证组合效果。这比一次宣称支持很多网络更容易定位方法贡献。GRU 必须核对 reset 位置与门顺序，MobileNet 的 depthwise 候选必须检查逐次累加与量化时点；名字相同不保证源模型、工程文档和目标原语语义一致。

## 三个候选研究问题

### A. 可核验的 SNN 语义合法化与 X1 原语映射（主线候选）

**问题：**对受限且明确的 SNN 子集，能否自动区分“精确可映射”“需要声明近似”“不支持”，并输出足够诊断信息？

**方法假设：**以状态转移契约识别神经元子图，原语能力表提供类型、数值、时序和状态条件；规则附带来源映射与边界测试，拒绝条件不满足的融合。

**比较基线：**按层名字/固定模板直接映射；无状态/时间检查的结构校验；手写映射与独立整数参考。朴素基线失败也要记录，不能通过修改源模型偷偷使其成功。

**指标：**支持条件覆盖、边界测试通过率、错误接受/错误拒绝案例、逐状态/脉冲一致、首次分歧定位、编译诊断；量化任务精度另列。精确映射对子集要求一致，不使用未经解释的宽容差。

**最小实验：**单神经元→FC-LIF 短链→两层跨核网络；先固定逻辑时间和整数规则，再导入一种明确表达状态的 ONNX 导出协议，可选加入 NIR 同义输入对照。通用 ONNX 模式识别、任意控制流和任意神经元不作为第一阶段承诺。

**可证伪条件：**同一契约下仍出现不可解释轨迹分歧；契约几乎只能手填、无法提高正确覆盖；只有最终准确率而没有状态证据。此时应缩小支持范围或重新定义方法，不宣称解决通用 SNN 编译。

### B. 状态与布局感知的 X1 内存/原语组规划（工程基础上的增量）

**问题：**相较仅按总容量分 stage，显式 bank、填充、活跃区间与持久状态的规划能否扩大合法模型范围、减少峰值占用或搬运？

**基线：**固定手写地址；仅容量贪心切分；生命周期复用但不考虑状态；本文方案。固定算子、整数语义、核预算和可用硬件能力。故意忽略状态的基线若错误，仅用于正确性对照，不作为同等正确性能基线。

**指标：**合法成功率、各 bank 峰值、填充字节、状态与控制占用、搬运量、PI 组数、编译时间及验证开销。用小案例穷举检查规划结果，大网络不宣称全局最优。

**最小实验：**LeNet 回归后，扫描 Conv 尾通道/非对称 padding、FC 块和 LIF 状态规模，再测 Conv→Flatten→FC 和分支/归约。必须证明重用区间不重叠，不能把硬件回绕当越界合法。

**增量边界：**P03 已有布局消除和同义原语选择，P05 已有资源调度。贡献须明确落在本目标的可检查约束、状态生命周期或联合选择的可量化改进，而不是重命名已有方法。

### C. 带控制通信与校准成本的切分—放置—时序协同（后续候选）

**问题：**加入包数、halo/部分和类别、bank 争用和跨组握手成本，比容量均衡/跳数最少更能预测并优化真实瓶颈吗？

**实验：**先用小通信图校准启动、长度、距离和并发；再比较均匀/非均匀分块、仅跳数放置和带时序成本的放置。只枚举当前 X1 已证实支持的调度，改造架构另设 profile。

**指标：**预测误差、首结果延迟、稳态吞吐、phase 等待、缓存峰值、搜索耗时；数据量、精度、核数和时钟固定，报告不同拓扑与随机种子。没有实机或可靠时序模拟时，只称模型预测改进，不称芯片加速或能耗下降。

**风险：**P05 已经深入研究这一路线，且片间通信、完整 SDK 支持需要额外资料。它比 A/B 更依赖性能计量和硬件条件，不宜在首版编译器闭环前铺开。

## 建议执行顺序与停止条件

1. **规格/实现审计。** 定版本、能力表、地址单位、p08 边界和可信参考；规格矛盾留 issue，有疑点不猜。解决验证设施的空实现和漏测覆盖问题后，才建立基线。
2. **ANN LeNet 闭环。** Parser→语义 IR→整数/布局→单核原语组→正式 JSON→仿真。最初可与手写配置逐项对照；优化后以语义输出为准，不强求地址相同。只成功运行随机初始化不代表训练模型导入正确。
3. **最小 FC-SNN 闭环。** 固定一种更新顺序，显式权重/状态/输入序列和样本复位，验证多步轨迹；再考虑 SHD/SoundSNN。现有模型的 checkpoint 形状、缺失路径和旧 import 应先审计，不能直接把历史脚本当无条件黄金基准。
4. **一次只引入一种复杂性。** 加多核通信，再加更大状态/卷积，再加分支或反馈。每阶段保留反例和拒绝诊断。
5. **选择一个主要研究增量做消融。** 优先 A，若语义子集很窄但资源规划形成可靠结果则以 B 为主；C 留作扩展。先定义基线、指标和失败标准，再实现优化，避免事后挑成功模型。

不要在没有闭环时同时承诺全 ONNX、全 NIR、全神经元、全硬件自动最优映射。MLIR 可作为后续承载基础设施；首版 Python IR 同样可以实现上述契约与实验。比较框架优劣需固定映射算法，不把算法变化误归因于工具。[P09，第5、11、17页](逐篇笔记/P09_MLIR.md)。

## 在正式选题前仍需补齐的证据

- 作者工具/源码能否获取和复用、许可证、IR 协议及当前 SDK 版本；本轮没有读取论文外补充材料或在线仓库。
- 目标 ONNX 模型究竟如何导出时间、状态、初值和自定义神经元；checkpoint 内容由注册/导出方式决定，不能笼统断言参数或状态从不保存。
- NIR 选定版本的实际节点与离散化实现，而不是用 2024 论文表格代表最新包；BIVM/SNN-MLIR 若接入须核实真实前端与后端接口。
- 规格内部容量/PI/FIFO/路由边界的矛盾、p08 时间窗关闭的实际行为，以及模拟器与实机版本。
- 扩展领域文献检索和已有工具对照。这里提出的是**候选增量**，没有证明 A/B/C 具有全球首次性。
