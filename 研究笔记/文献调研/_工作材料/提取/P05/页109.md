图 4.5 延迟与死锁 
如上图 4.5 所示，当多个路由包通过了一个 core 的某一个相同的端口，例如
上图的 1 号 core 东边的输入端口被 2 号和 3 号 core 同时占用，因此在这个地方存
在延迟等待。并且 0 号 core 的东边输入端口也被 3 个同时占用导致发生延迟。整
体的传输时间为传输单个的三倍时间，因此延迟为的 2 倍数据传输时间。对于上
图下侧部分，图中 1 号 core 虽然被经历两次，但是由于传输的端口和路径不同，
向左传输和向右传输是独立并行的，因此不存在延迟。 
图 4.5 的右下方为死锁示意图。A 号 core 的南部输出端口被 A、D 同时占用；
B 号 core 的西部输出端口被 A，B 同时占用；C 号 core 的北部输出端口被 B，C 同
时占用；D 号 core 的东部输出端口北 C，D 同时占用。因此 A 号 core 需要等待 D
号 core 被吸收，B 号 core 等待 A 号 core 的数据被吸收，C 号 core 等待 B 号 core
发出的数据被吸收，D 号 core 需要等待 C 号 core，形成无限等待环路，因此陷入
死锁。 由于死锁情况比较复杂，下面给出几个类似死锁但不是死锁的情况。 如下图
