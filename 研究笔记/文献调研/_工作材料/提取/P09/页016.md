C. Fortran IR (FIR)
[34]
LLVM Fortran 前端“flang”目前正由 NVIDIA / PGI 主
导进行重大开发。与 Swift、Rust 等语言类似，flang 需要
一种专门的中间表示（IR），以支持高性能 Fortran 代码库
的高级转换，并采用 MLIR 来实现这些 Fortran 特有的优化
。这些高级优化——包括高级循环优化、数组复制消
除、调用特化、去虚化——若仅使用 LLVM 则难以实现。
例如，FIR 能够将 Fortran 虚拟 Dispatch 表建模为一个
一等概念（参见图 8）。
// 类型 (u) 的分发表
fir.dispatch_table @dtable_type_u {
fir.dt_entry “method”，@u_method}
函数@some_func () {
%uv= fir . alloca ！fir . type<u> : ！fir . ref<！fir . type<u>>
fir.dispatch "method"(%uv) : (!fir.ref<!fir.type<u>>) -> ()
// ...
}
图 8。FIR 对动态虚拟函数调度表具有一阶支持。
在结构化中间表示中建模编程语言的高层语义的能力非
常强大。例如，对调度表的一级建模，可以实现一个稳健
的去虚化处理流程。尽管这也可以用定制化的编译器中间
表示来实现，但使用 MLIR 使得 flang 的开发人员能够将
工程资源集中在其领域特定的中间表示设计上，而不是重
新实现基础基础设施。
选择 MLIR 还释放了其他非 Fortran 特定方言的可重用
性：一种与语言无关的 OpenMP 方言可以在 Fortran 和 C
语言前端之间共享。同样地，使用 OpenACC 针对异构平
台的目标，在 MLIR 中通过共享和重用面向 GPU 的方言
及传递机制，也变得可行。这得益于 MLIR 专门设计以支
持多种可组合方言的特性。

优化 MLIR 模式重写：MLIR 拥有一个可扩展的模式
重写系统。除了静态声明的模式外，我们还遇到一些应用
场景，其中重写模式需要在运行时动态扩展，以便硬件厂
商在驱动程序中添加新的降序规则。解决方案是将 MLIR
模式重写本身表达为一种 MLIR 方言，从而利用 MLIR 基
础设施实时构建并优化高效的有限状态机（FSM）匹配器
与重写器。这项工作还包括在其他系统中可见的 FSM 优
化，例如 LLVM SelectionDAG 和 GlobalISel 指令选择系
统。

术，以其快速评估速度和可解释性著称。该编译器的前身
曾采用 C++ 模板实现，这虽能通过元编程生成高性能代

MLIR 被用作这一特定领域中新编译器的基础，该编译
器采用了一种专门的搜索方法驱动——实际上，这相当于

器耗费了三人月的开发时间，在生产模型上实现了高达 8
倍的性能提升，同时提高了编译过程的透明度。
V. MLIR 设计的后果
MLIR 设计有助于在复用现有通用抽象的同时，构建新
的语言和编译器抽象。实际上，许多问题的解决方案是
“添加新的操作符、新的类型”，这些操作符和类型可能
被整合到一个“新的方言”中。这是编译器工程领域的一
次重大设计变革，它带来了新的机遇、挑战与洞见。本节
将探讨其中的一些方面。
A. 可重用编译阶段
能够在一个 IR 中表示多个抽象层次，这促进了跨这些
层次运行的传递操作。 MLIR 通过逆转常见方法来处理可
扩展性：由于操作数量多于传递操作，操作更容易了解传
递操作。这也有助于提高模块化程度，因为方言特定逻辑
是在方言内部实现，而非在核心转换中实现。由于传递操
作很少需要了解操作的所有方面， MLIR 采用以下机制来
实现通用传递操作。
操作特性：许多常见的“核心”编译器优化 Pass（例如
死代码消除或常用子表达式消除）都依赖于诸如“是否为终
止操作”或“是否为可交换操作”等简单属性。我们将此类
属性定义为Op Traits。一个 Op 无条件地具备某项特性，例如
“标准分支”Op 始终是一个终止操作。对于许多优化 Pass 而
言，只需知道一个 Op 拥有一组可用于对其操作的特性即可，
