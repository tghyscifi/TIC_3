3. 多源异步时序簇的众核分组
3.1 芯片顶层设计概述
Tianjic X1 芯片仍然采用 2D Mesh 众核（Core）阵列和片上网络 NoC 架构，包含 160 个
功能核（Core），构成了 16×10（NS×WE）的阵列。每个核拥有一个 Core 间路由器，用于完
成本核数据的传输及其他核数据的中转。每个芯片在四个边上各有一个片间路由模块，用于
数据的缓存、整理和跨片传输。
如图 3- 1 所示，Tianjic X1 的时序上控制上具有两级的触发周期：相位（Phase）触发和
节拍（step）触发。相位周期是功能核的基本任务执行周期，在每个相位周期内，每个功能核
解析并执行一组静态原语组或者一组即时原语组。一个节拍周期内，包含多个相位周期，每
个功能核执行完原语组堆栈中的静态原语组和一定数量的由其他功能核触发的即时原语组。
在不同的节拍周期，功能核重复执行相同的静态原语堆栈；而即时原语组会由于触发 Core 的
时序周期可能和执行 Core 的时序周期不同而可能存在不同。
图 3- 1 多原语执行时序示意图
如图 3- 2 所示，芯片共可以分为 4 个节拍时序组和 32 个相位时序组，分别对应 4 个节
拍控制器和 32 个相位控制器。160 个功能核可以被任意的分配到 32 个相位时序组中，同样
的，32 个相位时序组可以被任意的分配到 4 个节拍时序组中。
NOTE：本章节，下文描述中，“[S]”表示 4 个节拍组，“[X]”表示 32 个相位组；“[i]”表示
160 个 core。不再逐一注释。

3.2 多节拍触发组
在节拍触发上，Tianjic X1 共有 4 个节拍触发组，产生 4 个独立的节拍触发信号，这 4 个
节拍触发组的模式受到外部四个对应的 trigger 控制。每当对应的外部 trigger[S]的上升沿到来
时，每个节拍触发器重新开始计数。
每 个 节 拍 触 发 控 制器 的 在 新的 Step 开 始 时会 给 出 trig_pos[S] 信 号 ，用 于 同 步 通 过
phase_grp_en[S]选择的一个或多个 Phase 时序组的 Phase 执行周期。每个节拍触发组对应的
Step 长度由预先的设置的时钟数控制，分为节拍开始结束时间（clock0_in_step[S]）和节拍强
制结束时间（clock1_in_step[S]）；当时钟计数大于节拍开始结束时间（clock0_in_step[S]）时，
如果对应的一个或多个 Phase 的 Phase 同时处于结束状态，产生新的 Step_finish[S]信号，结
束当前 Step。同样的，当时钟计数等于节拍强制结束时间（clock1_in_step[S]）时，无论对应
的一个或多个 Phase 的 Phase 是否同时处于结束状态，都会产生 Step_finish[S]信号，结束当
前 Step。
当产生 Step_finish[S]信号时，若此时外部的 trigger[S]信号处于高电平，节拍触发控制器
继续重新开始计数，进入新的 Step 周期，并产生 trig_pos[S]信号；否者节拍触发器等待 trigger[S]
的上升沿到来触发新的 Step 周期。
节拍时序信号用于同步其对应的一个或多个 Phase 时序组的周期性执行，在 trig_pos[S]
信号产生时同时也会有 Pck_grp[X]和 Sck_grp[X]信号产生。之后在一个 Step 内每个 Phase 时
序组会包含多个 Phase，每个 Core 在计算的时候执行原语堆栈中预配置的静态原语组和一定
数量的即时原语组。

3.4 异步相位组之间的数据交换
由于各相位组是由各自的相位控制器独立的运行产生，因此不同的相位组之间在 Phase
的运行上是异步的。当不同的相位组之间需要进行数据传输时，为了保证数据的完整性，通
过即时原语的“发送-应答-传输”机制来进行跨相位组的数据传输。
以图 3- 4 为例，core 0、core1、core2 属于 Phase_group1，core3、core4、core5 属于
Phase_group2，Phase_group1 的 3 个 core 需要给 Phase_group2 的 3 个 core 发送数据。此时，
配置 core0 的路由原语参数为需要发送一条即时原语包，需要收到一条即时原语应答；core1
和 core2 不需要发送即时原语，但是需要收到即时原语应答；core2 配置为需要返回即时原语
应答。

4. Controller Unit
4.1 模块概述及结构
Core 的运行由 Controller Unit，即 PI 处理器（PI processor）控制管理。Controller 负责根
据预置的静态原语组堆栈信息，调用 Axon、Soma 和 Router 模块；Controller 也负责响应和处
理通过路由接受到的即时原语执行请求信息。Controller 中存储原语执行堆栈的索引信息。根
据索引信息，Controller 生成待执行的原语在 Memory 中的地址指针，并发送给 Axon、Soma
和 Router。各处理器收到原语启动信号后，到相应地址中读取原语参数、执行相应操作并将
执行状态反馈给 Controller。

4.2.1 静态原语组 static PI 的存储及索引方式
如图 4- 2 所示，在每一个 Core 中，多条静态原语参数被压缩存储在 Memory 中，起始地
址为 Addr_static_PI_base，通过存储在 Control Unit 里 Static_PI_Buf 中对应的静态原语组索引
信息来索引读出。在存储时，每组包括 Axon-Dendrite、Soma1、Router、Soma2 操作的一组
原语被存储在一起，而其中的空操作原语则被压缩不需要存储。对应的在 Control Unit 中存储
的原语索引信息为对应每一组内 Axon-Dendrite、Soma1、Router 和 Soma2 是否为有效原语的
指示标志。当需要有数据从 Mem0/1 直接/经过计算后通过 Router 发送出去时，需要通过 Soma1
操作实现数据的搬运；当 Router 接收到数据之后最终需要存储在 Mem0/1，通过 Soma2 操作
实现数据的搬运。预配置原语在 Memory 中的原语参数和在 Control Unit 中的原语索引均按执
行顺序排列，因此每条原语索引不需要存储额外的地址信息。每个 Core 支持最大支持 32 条
预配置原语，因此 PI_Idx_Buf 的大小为 32×4b = 128b，预备置原语在 Memory 中所需的存储
空间为不超过 32×32B×4 = 4KB。
4.2.2 即时原语组 instant PI 的存储及索引方式
即时原语的压缩存储时的方式与静态原语相似，但是除了表示各模块是否为有效原语的
A/S1/R/S2_valid 标志位（共 4bit）之外，还包括表示其在 Mem2 中相对于静态原语结束的偏
置位信息 PI_addr_offset（6bit，保证大于 16*4/2= 32），一个一个用于区分是来自同节拍时序
组还是不同节拍时序组的标志位。一个即时原语组中起始原语（第一个不为空操作的模块原
语 ） 的 地 址 索 引 方 式 为 Addr_static_PI+Addr_instant_PI_base +(PI_addr_offset * 2) ， 其 中
Addr_instant_PI_base 为即时原语参数存储的起始地址。即时原语组索引采用 instant_PI_FIFO

4.3 Controller 的控制逻辑执行调度
4.3.1 原语执行调度
每个 Core 有一个 5bit 相位控制器选择寄存器 Psel[i]。用于从 32 组相位控制器输出的
pck_grp[X]中选择一路作为本 core 的相位计算触发信号，而该组相位控制器选通的节拍触发
信号 sck_grp[X]亦同时成为本 core 的节拍触发信号。
在每一个 Phase 中，P_ck 触发后，功能核状态信号 Core_finish 被拉低，Core 内开始执行
新一组原语运算。Controller 判断即时原语组索引 FIFO 中是否存在需要执行的即时原语组，
如果满足即时原语组执行条件，执行 FIFO 中的一条即时原语组；否则，按照顺序执行一条
静态原语组。Controller 依次检索所执行原语组的 Axon、Soma1 和 Router 原语索引信息。如
果对应的原语请求不为空，则生成原语参数在 Memory 中的地址和读请求发送给对应执行单
元。Axon-Dendrite、Soma、Router 模块在接收到 PI 原语的存储地址，并从 Memory 中读取完
参数之后，会将各自对应的 idle 信号拉低（Router 包括 Send_idle 和 Receive_idle）；当执行完
各自操作以后或不需要执行原语时，idle 信号为高。在 Soma 执行完 Soma1 原语 S_idle 为高
或者不需要执行原语时，等待 Router 的 Receive_idle 为高，则 Soma 会根据 S2_valid 是否为 1
继续执行 Soma2 原语。之后在各个模块执行完静态原语之后，会将各自对应的 A_idle、S_idle
和 Send_idle 和 Receive_idle 信号由低转高。等到对应各模块的 A_idle、S_idle 和 Send_idle 和
Receive_idle 信号都为由低转高后，会拉低 Core_busy 状态信号，表示完成当前 Phase 操作完
成，此时 Core 可以进入低功耗模式。
4.3.2 与各模块间的交互
由于在 Tianjic X1 中，在每一个 Phase，Axon-Dendrite、Soma 和 Router 会出现某个模块
不工作的情况，为保证各个模块的之间的并行流水特性及不受单一模块是否开启的影响，采
用每个模块将自身运行状态反馈给 Control Unit，Control 根据内部逻辑产生各模块的工作使能
信号来保证各模块可以实现较好的分组并行特性。在每一个 Phase，Control Unit 在控制读取
完原语索引信息对每一个模块进行配置之后，即进入对三个模块的控制执行状态，直至三个
模块的操作都完成（idle 信号拉高）。
Soma 和 Axon 之间可以通过行流水的方式工作，Axon 每计算完 1 行，Controller 给 Soma
一个 S_row_trigger 信号。Soma 每收到一个 S_row_trigger 信号，in_row_cnt 加 1；同时 Soma
每计算完（输出的）一行，in_row_cnt 减去一个高度方向的 stride 值 Sy（或 1），即再等待 Sy
行输入 Soma 才能开始计算。当 in_row_cnt 大于卷积核高度（或 0）时，Soma 可以才计算。

5. Memory Unit
5.1 模块概述及结构
Core 内 memory 为多片 SRAM 构成的 144KB 存储空间，用于存放神经元网络计算的权
重、数据以及参数等，采用统一管理，灵活配置使用。
Core 内 memory 由 5 片读写宽度为 16B（128b）的物理 SRAM 块组成，为 32KB×4+16KB。
在逻辑上被划分为三块 Memory：Mem0（读写宽度为 32B，大小为 64KB）、Mem1（读写宽
度为 32B，大小为 64KB）和 Mem2（读写宽度为 16B，大小为 16KB）。如下图 4-1 所示。
此外还包含一块大小为 16B 寄存器（等效 Mem3，实际在 Router 模块中）用来存储待发
送的输出数据，此模块可用于 Soma 和 Router 的数据交互。
图 5- 1 Memory 单元的基本结构示意图
基本工作模式：
Mem0~1 为权重、数据空间：权重、数据均按 32B(256b)为宽读写；
Mem2 设定为参数、缓存空间：Soma 16B 读写；Router 1B、2B、8B 写、16B 读；
Mem3 设定为单向输出缓存：Soma 16B 写；Router 16B 读（实现为 Router 中的寄存器）。
5.2 SRAM 块配置使用方式
在基本工作模式（mode0）下，Mem0～Mem1 为计算（权重、数据）存储空间，Mem2
为参数存储空间，Mem3 为 Soma 到 Router 的缓存。
Mem0、mem1 在使用时可以被分别指定给数据存储、权重存储，由 Control Unit 配置。
即在执行∑X*W 计算时，尽量保证 X 与 W 存放在不同的物理 SRAM 块上（需考虑放在相同
