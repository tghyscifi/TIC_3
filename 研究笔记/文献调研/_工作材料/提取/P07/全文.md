1. 概述
1.1 设计定位
Tianjic X1 的设计目标是探索大规模时空复杂度的新计算架构。Tianjic V2 成功实现了对
计算机科学导向的传统人工神经网络和计算神经科学导向的脉冲神经网络的同时支撑和计算
架构上跨模态融合，在此基础上，Tianjic X1 旨在适应神经网络的高速变化带来的通用性需求，
进一步提高芯片的灵活性和可重构能力，从而同时实现对于多种神经网络的独立运行和异构
协同建模的高效支撑。
具体而言，芯片需要面对类脑神经网络算法中丰富多样性以及日渐增长的多网络协同工
作的趋势。
类脑算法具有丰富的多样性：1）编码方式的多样性：比如在传统神经元通过高精度的激
活值来进行信息的传递，而在脉冲神经元则通过用 0-1 表示的脉冲构成的序列来进行信息的
传递，更复杂的；2）网络结构的多样性：多个神经元可以通过不同的连接关系构成不同的网
络结构，常见的连接关系包括全连接结构、卷积连接和反馈连接等；3）存算负载的多样性：
在网络中的不同层，由于输入输出大小的不同以及结构参数的不同，会有不同的计算量和存
储量的需求。这些不同的多样性均需要芯片具有高的灵活性以支撑。
图 1- 1 类脑算法的多样性
多网络融合协同工作的趋势：随着处理问题的复杂程度不断增加，单一网络已经无法对
应，出现了多网络协同工作的趋势。不同类型的网络可以通过串联的关系顺序地处理统一任
务，也可以并行的协同辅助处理，此外，还可以通过网络之间的工作调度控制处理不同任务
的网络协同工作，从而构成一个大的系统。不同地网络不但可能在信息的传递处理上存在不
同，而且还可能具有不同的触发执行周期。实现多网络的高效协同对芯片设计提出了更高的
需求。

2. 基于原语译码的多模块功能核（Core）
2.1 基于原语指令的配置方式
功能核设计采用基于原语指令译码执行的操作机制，每个功能核预留 16 条计算原语指令
（宏指令），每条原语的指令长度为 32B。原语分别由功能核中不同执行单元译码后执行。各
原语执行单元在功能核控制单元的调度下从核内存储单元中读取指令单元参数，之后对原语
进行译码，并根据原语指令的译码结果，从核内存储单元中（或者从核间路由接口接收数据）
读取数据，执行相应的操作，再将核内存储单元中去（或者发送到核间路由网络中）。

2.2 功能核的模块划分
按照原语的调度、执行和数据存储的需求，功能核被划分为了 Controller、Memory、Router、
Axon、Dendrite 以及 Soma 这 6 个功能单元，如下图 2- 1 所示。
其中：
Control Unit： Core 的运行控制单元，实现基于原语的指令调度；
Memory Unit： 多片 SRAM 构成的存储空间，用于存放神经元网络计算的权重、数据以
及参数等，采用统一管理，灵活配置使用；
Axon Unit： 实现向量、矩阵运算的输入输出数据的读写及类型转换等；
Dendrite Unit： 高并行的乘加计算（MAC）阵列，和 Axon 共同进行矩阵/向量计算；
Soma Unit： 实现 Core 内的数据搬运、张量比较以及 LUT 激活函数和 LIF 神经元等
非线性运算；
Router Unit： 实现 Core 间各类数据传输的路由控制逻辑。
图 2- 1 Tianjic X1 的功能核（Core）结构示意图
1. Core 的运行由 Controller Unit，即 PI 处理器（PI processor）控制管理。PI 处理器负责
根据预置的静态原语组堆栈信息，调用数据处理器（Data Processor，即 Axon Unit）、神经元
处理器（Soma Unit）以及路由处理器（Router Unit）；PI 处理器也负责响应和处理通过路由
接受到的即时原语执行请求信息。PI 处理器中存储原语执行堆栈的索引信息。根据索引信息，
PI 处理器生成待执行的 PIC 在 Memory 中的地址指针，并发送给数据处理器、神经元处理器
及路由处理器等。各处理器收到 PIC 启动信号后，到相应地址中读取 PIC 全码、执行相应操
作并将执行状态反馈给 PI 处理器。

2. 数据处理器(Axon Unit)根据 PIC 参数，从 Memory 中读取待处理的数据 InA 及 InB，
经数据格式整理、类型变化后，逐时钟送到矩阵处理器。并将矩阵处理器的计算结果，如膜
电位累加值，写回 memory 中。数据处理器仅用于高速处理大并行度向量、矩阵计算任务，
不参与 Core 间数据收发。
3. 矩阵处理器（Dendrite/Matrix）为高速并行乘加器（MAC）阵列，不直接访问 memory。
矩阵处理器的输入输出数据及其计算过程均由数据处理器（Axon Unit）管理。Axon 模块的
译码结果决定着乘加器阵列中的乘加器的工作模式、开启数量和阵列组织方式。
4. 神经元处理器（Soma）用于从 Memory 中读取数据，进行数据比较、数据搬运整理和
神经元的非线性变换操作。神经元处理器可以访问 Memory 模块中用于数据收发缓存的空间，
从而参与 Core 间数据收发。神经元处理器（Soma）可以将待发送数据搬运到发送缓存区或
者将接收缓存区中存储的数据搬运出来。
5. 路由处理器（Router）用于 Core 间数据收发、数据的中继、多播以及即时原语组执行
请求和应答信号的传递。
6. 存储模块（Memory）为多片 SRAM 构成的 144KB 存储空间，用于存放神经元网络计
算的权重、数据以及参数等，采用统一管理，灵活配置使用。当来自执行单元的不同数据接
口出现 Memory 的访问时，由存储模块按照预定优先级进行仲裁。

的 索 引 信 息 控 制 各 执 行 单 元 的 译 码 执 行 （ 即 一 个 工 作 周 期 内 功 能 核 需 要 处 理 一 条
Axon-Dendtire 原语，一条 Router 原语和两条 Soma 原语），我们称这样的一组 A-S1-R-S2 的

每个 Core 可以处理由多个原语组构成的原语组堆栈，在生成芯片的配置时，原语组堆栈
会被转化为 Controller 中的多组原语组索引信息和 Memory 中的多条原语参数信息。在每个工
作周期时，由 Controller 读取一组原语组索引信息生成相应的地址指针，控制 Axon、Soma
和 Router 模块从 Memory 中读取对应的原语参数译码执行。
由于存储和触发执行的机制不同，一条原语组的在执行上会被分为静态原语组合即时原
语组。
静态原语组：由执行 Core 的 Controller 从内部自动连续调用执行。需要执行的静态原语
组的原语指令参数按照原语组执行顺序连续的存储在 Memory 中，每个原语组中各原语的执
行情况（是否执行）作为索引被存储在 Controller 的静态原语组索引寄存器中，在执行时
Controller 依次从静态原语索引寄存器中读取一组原语的索引信息并控制各模块从 Memory 中
读取原语指令参数并执行。
即时原语组：由其他的 Core 触发执行 Core 执行。需要执行的即时原语组的原语指令参
数预先存储在 Memory 中，与之对应的即时原语索引信息除了原语组内各模块的执行情况之
外，还包括了即时原语存储位置（位置偏置）信息。即时原语索引信息存储在触发 Core 中，
由触发 Core 发送包含即时原语信息的即时原语路由包触发执行 Core 来执行。

3. 多源异步时序簇的众核分组
3.1 芯片顶层设计概述
Tianjic X1 芯片仍然采用 2D Mesh 众核（Core）阵列和片上网络 NoC 架构，包含 160 个
功能核（Core），构成了 16×10（NS×WE）的阵列。每个核拥有一个 Core 间路由器，用于完
成本核数据的传输及其他核数据的中转。每个芯片在四个边上各有一个片间路由模块，用于
数据的缓存、整理和跨片传输。
如图 3- 1 所示，Tianjic X1 的时序上控制上具有两级的触发周期：相位（Phase）触发和
节拍（step）触发。相位周期是功能核的基本任务执行周期，在每个相位周期内，每个功能核
解析并执行一组静态原语组或者一组即时原语组。一个节拍周期内，包含多个相位周期，每
个功能核执行完原语组堆栈中的静态原语组和一定数量的由其他功能核触发的即时原语组。
在不同的节拍周期，功能核重复执行相同的静态原语堆栈；而即时原语组会由于触发 Core 的
时序周期可能和执行 Core 的时序周期不同而可能存在不同。

如图 3- 2 所示，芯片共可以分为 4 个节拍时序组和 32 个相位时序组，分别对应 4 个节

3.2 多节拍触发组
在节拍触发上，Tianjic X1 共有 4 个节拍触发组，产生 4 个独立的节拍触发信号，这 4 个
节拍触发组的模式受到外部四个对应的 trigger 控制。每当对应的外部 trigger[S]的上升沿到来
时，每个节拍触发器重新开始计数。
每 个 节 拍 触 发 控 制器 的 在 新的 Step 开 始 时会 给 出 trig_pos[S] 信 号 ，用 于 同 步 通 过
phase_grp_en[S]选择的一个或多个 Phase 时序组的 Phase 执行周期。每个节拍触发组对应的
Step 长度由预先的设置的时钟数控制，分为节拍开始结束时间（clock0_in_step[S]）和节拍强
制结束时间（clock1_in_step[S]）；当时钟计数大于节拍开始结束时间（clock0_in_step[S]）时，
如果对应的一个或多个 Phase 的 Phase 同时处于结束状态，产生新的 Step_finish[S]信号，结
束当前 Step。同样的，当时钟计数等于节拍强制结束时间（clock1_in_step[S]）时，无论对应
的一个或多个 Phase 的 Phase 是否同时处于结束状态，都会产生 Step_finish[S]信号，结束当
前 Step。
当产生 Step_finish[S]信号时，若此时外部的 trigger[S]信号处于高电平，节拍触发控制器
继续重新开始计数，进入新的 Step 周期，并产生 trig_pos[S]信号；否者节拍触发器等待 trigger[S]
的上升沿到来触发新的 Step 周期。
节拍时序信号用于同步其对应的一个或多个 Phase 时序组的周期性执行，在 trig_pos[S]
信号产生时同时也会有 Pck_grp[X]和 Sck_grp[X]信号产生。之后在一个 Step 内每个 Phase 时
序组会包含多个 Phase，每个 Core 在计算的时候执行原语堆栈中预配置的静态原语组和一定
数量的即时原语组。

4. Controller Unit
4.1 模块概述及结构
Core 的运行由 Controller Unit，即 PI 处理器（PI processor）控制管理。Controller 负责根
据预置的静态原语组堆栈信息，调用 Axon、Soma 和 Router 模块；Controller 也负责响应和处

据索引信息，Controller 生成待执行的原语在 Memory 中的地址指针，并发送给 Axon、Soma
和 Router。各处理器收到原语启动信号后，到相应地址中读取原语参数、执行相应操作并将
执行状态反馈给 Controller。

4.2.1 静态原语组 static PI 的存储及索引方式

4.3 Controller 的控制逻辑执行调度
4.3.1 原语执行调度
每个 Core 有一个 5bit 相位控制器选择寄存器 Psel[i]。用于从 32 组相位控制器输出的
pck_grp[X]中选择一路作为本 core 的相位计算触发信号，而该组相位控制器选通的节拍触发
信号 sck_grp[X]亦同时成为本 core 的节拍触发信号。
在每一个 Phase 中，P_ck 触发后，功能核状态信号 Core_finish 被拉低，Core 内开始执行
新一组原语运算。Controller 判断即时原语组索引 FIFO 中是否存在需要执行的即时原语组，
如果满足即时原语组执行条件，执行 FIFO 中的一条即时原语组；否则，按照顺序执行一条
静态原语组。Controller 依次检索所执行原语组的 Axon、Soma1 和 Router 原语索引信息。如
果对应的原语请求不为空，则生成原语参数在 Memory 中的地址和读请求发送给对应执行单
元。Axon-Dendrite、Soma、Router 模块在接收到 PI 原语的存储地址，并从 Memory 中读取完
参数之后，会将各自对应的 idle 信号拉低（Router 包括 Send_idle 和 Receive_idle）；当执行完
各自操作以后或不需要执行原语时，idle 信号为高。在 Soma 执行完 Soma1 原语 S_idle 为高
或者不需要执行原语时，等待 Router 的 Receive_idle 为高，则 Soma 会根据 S2_valid 是否为 1
继续执行 Soma2 原语。之后在各个模块执行完静态原语之后，会将各自对应的 A_idle、S_idle
和 Send_idle 和 Receive_idle 信号由低转高。等到对应各模块的 A_idle、S_idle 和 Send_idle 和
Receive_idle 信号都为由低转高后，会拉低 Core_busy 状态信号，表示完成当前 Phase 操作完
成，此时 Core 可以进入低功耗模式。
4.3.2 与各模块间的交互
由于在 Tianjic X1 中，在每一个 Phase，Axon-Dendrite、Soma 和 Router 会出现某个模块
不工作的情况，为保证各个模块的之间的并行流水特性及不受单一模块是否开启的影响，采
用每个模块将自身运行状态反馈给 Control Unit，Control 根据内部逻辑产生各模块的工作使能
信号来保证各模块可以实现较好的分组并行特性。在每一个 Phase，Control Unit 在控制读取
完原语索引信息对每一个模块进行配置之后，即进入对三个模块的控制执行状态，直至三个
模块的操作都完成（idle 信号拉高）。
Soma 和 Axon 之间可以通过行流水的方式工作，Axon 每计算完 1 行，Controller 给 Soma

行输入 Soma 才能开始计算。当 in_row_cnt 大于卷积核高度（或 0）时，Soma 可以才计算。

5.3 处理器访问 SRAM
Axon Unit 有两套数据总线，分别访问数据空间、权重空间。InB 总线为读写数据总线，
控制从权重空间读出权重数据 W，写回 W 更新数据；InA 总线为读写总线，控制从数据空间
读出输入数据 X，并将计算结果 V 写回数据空间。
Axon Unit（数据处理器）的内存读写数据位宽为 32B，地址溢出指定数据空间大小时，
地址取余数。数据处理器访问优先级最高。
Soma Unit（神经元处器）有两套读写分离的地址数据总线，可以读写任意 SRAM 块
Mem0～Mem3，以提高 Move 原语执行的效率。读写数据位宽为 16B，地址溢出指定 memory
块大小时，地址取余数。
Router Unit（路由处理器）有一套读写地址数据总线，只访问参数空间 SRAM 块 Mem2。
路由处理器的读出位宽为 16B，写入数据位宽为 8B、2B 和 1B。
工作时，路由器按 8B 接收数据，写入 Mem2 相应的地址输入数据缓存地址。当一组数
据传输完整后，如每个 Phase 结束后或收到由发送端发来传输结束指令，由 Soma Unit 按 16B
位宽，根据原语将输入数据转移至数据存储空间中。
Axon Unit 将计算结果存入数据空间。当需要将 Axon Unit 计算结果发送到其它 Core 时，
由 Soma 处理器执行 Move 原语，根据原语中的地址将输出数据搬运到在 Router 中等效为
Mem3 的中间缓存中，再由路由处理器读取发送；或将数据直接存储 Mem2，再由路由处理
器读取发送。
Soma 处理器计算结果可以存入数据空间或 Mem2。当需要发送到其它 Core 时，Soma 处
理器可以直接将结果存入 Mem2 或 Mem3 中，由路由处理器读取发送。其中，Mem3 为 16B
寄存器组成的缓存单元，用于缓存 Soma 向 Router 发送需要 Core 间传输的数据。当 Soma 写
该缓存后该缓存写使能清 0，Router 发送器读取该缓存后，该缓存写使能置 1。
Mem0~Mem2 访问优先级：Axon Unit＞Soma Unit＞Router Unit。
进 一 步 ： (Read_PI) >Axon_InA RW > Axon_InB RW ＞ Soma Wr>Soma Rd ＞ Router
Rd>Router Wr。

Core 间路由可以分为路由包收发和本地数据处理两层次，路由包从输入通道进入 core，
根据路由地址信息可以从其他三个方向输出通道任意一个输出，也可以处理本地数据的收发。
本地数据处理后面详述，路由包收发与天机 2 类似，此过程主要包含三个步骤:
(1) Routing，路由方向计算过程，确定路由包将要去往的输出通道；从配置寄存器读取
路由策略配置，R_Mode 配置为 00 或 01 时，由各输入通道给出的 dx, dy 信息，确定路由包
将要申请的输出通道，产生 req[20:0]信号;。req[20:0]每一位代表一个输入通道是否申请一个
输出通道，input_w 会申请除 output_w 以外的所有输出通道，因此共需要 4bits 来表征，input_e，
input_n, input_s 与之类似，特别的 Input_c 会申请五个输出通道中的任意一个，因此一共是
21bits。
(2) Arbitrator，仲裁，当多个输入通道同时申请同一输出通道时，根据优先级关系进行仲
裁；由各输出通道的申请状态(req[20:0]中的特定位)，依据 WENSC 的优先级对申请进行仲裁，
确定出获得此次输出通道使用权的输入通道；当 rdy 信号为 1 时，给出 sw 信号，控制 switch
模块将对应输入通道和输出通道连通，同时给出 ctr 信号，控制相应输入通道发出路由包。
(3) Switch，通过交叉开关将输入通道和对应输出通道连接起来进行路由包传输。交叉开
关（Switch）模块将五个输入通道（含 local 输入）和五个输出通道（含 local 输出）全连通。
Core 间传输支持两种路由策略（可配置，芯片控制寄存器）。0：先 X 后 Y 维序路由； 1：
先 Y 后 X 维序路由。

发送过程（Merge）:
(1) 与处于芯片边缘的 core (x 方向 16 行，y 方向 10 列)互连，接收与它互连的 core 发来
的数据；
(2) 将芯片边缘 16/10 个 core 视为 16/10 个输出通道，对于有数据发出的通道采用轮询的
方式，平均分配时间片，每个通道分得的时间片允许一个路由包通过；
(3) 对于分配到时间片的通道，若为 W、E 方向根据通道所处位置和路由包中 dy 信息，
改写 dy（改写规则见 Merge 过程描述），若为 N、S 方向根据通道所处位置和路由包
中 dx 信息，改写 dx（改写规则见 Merge 过程描述）；
将路由包进行并串转换，并检测与他互联的芯片接收是否 ready, 若是则通过 SerDes 将路
由包发出；
接收过程（Split）:
(1) 接收 SerDes 发来的路由包；
(2) 若是 W、E 方向发来的路由包，若判断|dx|＞16 则将路由包跨过本芯片该方向上所有
core，直接发给原包前进方向上的 Merge 模块，实现路由包跳片传输；若判断|dx|≤16，
|dy|＞16，则直接将原包发送给 N 或者 S 方向的 Merge 模块，进行 Y 向的跨片传输。
（此功能由 R_Skip_en 配置寄存器控制使能）
(3) 若是 W、E 方向发来的路由包，若判断|dx|≤16、|dy|≤10 则根据 dy 信息确定此包发给
的通道号，并在发送前更新 dy 信息（见 Split 过程描述），将路由包发给对应通道；

10.3.3 跳片配置方法

 主板上横向排列的一排芯片，以最左侧芯片的 S 边 (Tx, Rx)作为主机配置接口.

 上行内容（读数据）从 N 到 S 传递

 CoreID 由主机下发，固定为 15.
 硬件自动完成：从 S 到 N 每跳一个芯片，ChipID 减 1，减到 0 即为选中当前要配置的芯
