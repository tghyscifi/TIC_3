B. 数值保真度
II
在浮点模式下，编译后的输出与两个网络的参考值在位精度
上完全一致：每个输出单元均匹配，且总脉冲计数完全相同（表
）。这证实了该方言、其降阶处理以及 C 语言运行时环境均能
精确复现源框架的动态行为，且在离散化时间步长循环过程中不
存在任何偏差。
在量化为 int8 的模式下，输出结果不再具有位精确性——这
与精度降低的预期一致；但最重要的成果在于跨目标平台的一致
性：在 x86 平台和 X-HEEP RISC-V 平台上，针对 snn_oxford 数据
集的准确率均为 99.585%，针对 snntorch 数据集的准确率均为
92.000%；且在这两台设备上所使用的不匹配神经元单元及脉冲
计数均完全一致。由于该量化过程仅采用整数运算且基于位移操
作，因此编译后的神经网络在两种截然不同的指令集环境下均具
有确定性。嵌入式目标平台上的计算结果并非桌面端结果的近似
值，而是与之完全等同。残差误差与浮点数参考值之间的差异程
度因具体网络而异：对于 snn_oxford 数据集而言，该误差可忽
略不计（_0.4%，即在 100 个时间步长内仅存在一个脉冲的净差
异）；而对于 snntorch 数据集，则为中等程度（_8%）。

C. 便携性与占地面积
III
该同一条 NIR 图生成了用于 X-HEEP RISC-V 核心的 x86 二进制
交叉编译结果，且该图内容保持不变，仅 C 编译器有所不同。
目标平台上的内存占用情况（表 ）可清晰地分为两部分：代
码与运行时占用空间固定为≈ 12.6 KB（占 128 KB 指令区域的
9.6%），且在两种网络中完全一致；这部分内容由时间步长内
核、memref连接层以及堆栈构成，这些部分均与模型无关。数
据占用空间则随模型规模而变化，其中 i8 权重矩阵占据主导地
位：snn_oxford 的数据占用空间为 114 KB（占 256 KB 数据区域
的 43.6%）， 而 snntorch 的 数 据 占 用 空 间 为 172 KB（ 占
67%）。
这种差异正是实际部署中的便携性考量所在。两种模型
均可适配于中端微控制器，但更大的SNN则无法部署在
Arduino级器件或低端STM32等小型设备上——这些设备
仅配备数十KB的内存。因此，部署特定网络时的关键限制
因素在于模型尺寸，而该尺寸几乎完全由权重参数决定；
这正是量化技术所要解决的难题：缩减权重占用的存储空
间，从而拓展网络可适配的器件范围。相比之下，固定约
12.6 KB的内核参数则从来不是制约因素。

D. 基线对比
IV
为更好地理解编译后的二进制文件，我们将其每步计算成本
与在同台 x86 主机上使用原始 Python 框架运行相同网络所产生
的成本进行对比（表 ）。该框架的基准值较高：对于 snn_
oxford，每步需173.3 百万次周期；对于snntorch 则为 194.0 百
万次周期，这是因为每一步都包含了 Python 解释器与深度学习
运行时的全部开销——即张量分配、指令调度及库调用开销，
这些开销在每个时间步均需重复计算。而 snn-mlir i8 二进制文
件执行相同步骤所需的周期分别为651k和1.23M，比前者低两个
至三个数量级（≈ 266 × and ≈ 157 ×）；而位精确浮点数二进制
文件的周期则分别低 213 ×和 118 ×。
这并非一项关于峰值性能的宣称。对于运行在 CPU 上的小型
网络而言，该框架的单步执行时间主要受固定解释器开销影
响——该开销与网络的算术运算无关；在 2.04 GHz 频率下，单
步耗时约为 85–95 毫秒，而使用编译后的二进制文件时，该耗
时远低于 1 毫秒。关键在于这一开销对嵌入式部署意味着什
么：使用框架时，必须携带解释器及其所有依赖项才能执行单
个时间步；而 snn-mlir 生成的产物则是一个独立的 C 语言二进制
文件，无需携带上述任何组件。移除这一堆栈结构正是使该网
络能够部署在裸机嵌入式目标设备上的原因；正是生成上述 x86
平台性能数据的同一份二进制文件，被用于在 X-HEEP 平台上运
行。
