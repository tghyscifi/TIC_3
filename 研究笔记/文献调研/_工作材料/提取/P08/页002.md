SNN - MLIR ：一种用于将神经形态SNN从 NIR 编
译为 Bare-Metal C 的 MLIR 方言
亚历杭德罗·加西亚·赫内尔 ∗，阿尔瓦罗·罗隆·德·皮内多 ∗,
摘要 ——脉冲神经网络（SNNs）目前越来越多地在多种不同
的框架（snnTorch、Lava、Norse等）中进行训练，而这些框架
均采用各自独立的模型格式。神经形态中间表示（NIR）通过提
供一种通用且与框架无关的格式来解决这一碎片化问题，用于交
换已训练的 SNN 模型。 NIR 解决了模型交换问题，但仅止于
此；它仅提供对神经网络的描述，而非运行该网络的具体路径。
各后端仍需自行实现部署流程，其间缺乏一个可共享且可转换的
编译器表示层。本文介绍了snn-mlir——一个面向 SNNs 的独立
于树（out-of-tree）的 MLIR 方言，以及一个 NIR → MLIR →C 编
译桥接方案。该方言提供了一组小型的类型多态性操作，这些操
作在浮点数（f32/f64）与量化数据（i8/i32）上均能完全一致地
执行，因此单个中间表示既适用于仿真场景，也适用于面向硬件
的部署场景。Python 前端可读取任意 NIR 文件并生成该方言的
中间表示（IR），并自动插入重缩放操作，以确保各层间的量化
尺度保持一致。参考降阶阶段将方言转换为标准线性代数 与算
术 运算，随后工具链生成自包含、无依赖关系的 C11 代码，该
代码可在任何支持 C 语言的 CPU 或嵌入式目标平台上编译并运
行。我们针对参考输出评估了数值保真度、跨 CPU 目标的可移
植性以及量化成本。当前研究范围限于采用 CPU 后端的前馈全
连接网络。snn-mlir已根据Apache-2.0许可证（附带 LLVM 例外）
以开源形式发布，并已在 Github 上可供使用。
索引词 ——脉冲神经网络、神经形态计算、 MLIR 、 NIR 、编
译器、量化、边缘部署。
I. 引言
脉冲神经网络已从一种神经科学建模工具，发展成为适用
于边缘计算和嵌入式硬件低功耗推理的实用解决方案。其
基于事件驱动且具有状态保持特性的计算方式天然适配于
神经形态处理器，且日益适用于在严格能量与内存预算限
制下运行的传统微控制器。这种日益增长的关注度催生了
一个成熟的训练框架生态系统（snnTorch[1]、Lava[2]、
Norse[3]、Nengo[4]、Rockpool[5]、Sinabs[6]），每个框架
均能生成经过训练的模型。然而，这也带来了一个常见的
问题：各框架均采用独立的语言体系，因此在某一框架中
训练的模型难以直接在另一框架中使用，更不用说在目标
设备上部署了。
[7]神经形态中间表示（NIR） 的提出正是为了解决这一交换
问题。 NIR 定义了一个小型且与框架无关的神经元及突触原语
词汇集（包括漏积分-放电变体、线性及仿射连接），并允许任
何框架导出经过训练的模型。

将网络转换为通用的图结构格式。 NIR 获得广泛采用，正是
因为它对边界划分得非常清晰：它定义了网络的内涵，而有
意将部署过程排除在定义范围之外。对于一个交换格式而
言，这一做法是正确的，但同时也留下了一个空白。一旦模
型被转换为 NIR 格式，通往可运行可执行程序的路径仍然未
被明确定义；在实际应用中，每个后端都需要从零开始重新
实现这条路径——包括手动编写推理循环、针对特定目标平
台的代码，以及定制化的量化方案和运行时环境。在这种情
况下，不存在一种可被检查、转换并像编译器处理其他程序
那样逐步降级的共享表示形式。
[8]
我们认为，SNNs 需要一个合适的编译器中间表示，而
MLIR 是构建该中间表示的理想基础。 MLIR 正是为这类问
题而设计的：它支持自定义方言、显式类型标注，以及从领
域特定表示逐步降级为标准操作、最终生成机器码的过程。
通过将 SNNs 表述为一种第一类 MLIR 方言，我们使该网络成
为一个真正的编译器对象——即一个可被标准工具进行验
证、优化和重新目标化的对象，而非每个后端自行解释的晦
涩图结构。
本文介绍了一种面向SNNs的离树 MLIR 方言——snn-mlir，
以及一个将 NIR 模型编译为独立C代码的编译桥接工具。我
们的贡献如下：
1) 一种类型多态性 SNN 方言。一套紧凑的操作集用于
建模 CUBA- LIF 神经元家族及其线性突触。每个操作
在 f32 数据与量化后的 i8/i32 数据上均采用相同方式
执行，因此仿真与部署共享同一 IR 和同一组操作
集，无需维护独立的浮点数与整数操作集。
2) 支持自动量化尺度对齐的 NIR 桥接器。Python 前端
可读取任意 NIR 图形并生成方言 IR 代码；在量化模
式下，该桥接器会自动插入重标量操作，以对齐线
性层与神经元动态之间不同的定点量级——这一机
制在 NIR 生态中尚无对应方案，可消除手动实现量
化推理时常见的隐性错误来源。
3) 参考 CPU 降维：一个转换阶段将方言化操作重写为
标准的linalg和arith操作；现有 MLIR 和 LLVM 工具链
将这些操作编译为 LLVM IR，再编译为机器码。生成
的 C 语言运行时环境采用标准、无依赖的 C11 语言
编写，可由任何支持 C 语言的目标系统进行编译。
4) 对保真度与可移植性的评估：我们通过与参考输出结果进
行比对来验证数值计算的正确性；证明相同的中间表示
（IR）可在多种 CPU 及嵌入式目标平台上实现重新适配；
