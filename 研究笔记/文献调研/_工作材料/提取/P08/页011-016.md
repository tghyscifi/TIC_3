Infloat mode the compiled output is bit-exact with the
referencefor both networks: every output cell matches and
the total spike counts are identical (Table II). This confirms
that the dialect, its lowering, and the C runtime reproduce the
source framework’s dynamics exactly, with no drift across the

C. Portability and Footprint
The same NIR graph that produced the x86 binary cross-
compiles, unchanged, to the X-HEEP RISC-V core, only the C
compiler differs. On-target memory usage (Table III) separates
cleanly into two parts. The code and runtime footprint is
fixed at≈12.6 KB (9.6% of the 128 KB instruction region)
and is identical for both networks. It is the timestep kernel,
thememrefglue, and the stack, none of which depend on
the model. The data footprint scales with the model and is
dominated by the i8 weight matrices: 114 KB for snn_oxford
(43.6% of the 256 KB data region) and 172 KB for snntorch
(67%).
That contrast is the practical portability story. Both models
fit comfortably on a mid-range microcontroller, but bigger
SNNs would not fit on small devices such as an Arduino-class
part or a low-end STM32, which offer only tens of kilobytes
of RAM. The limiting factor for deploying a given network
is therefore the model size, set almost entirely by its weights,
and this is exactly what quantization addresses, cutting the
weight footprint and widening the range of devices a network
can reach. The fixed∼12.6 KB kernel, by contrast, is never
the obstacle.

VII. Limitations
The current implementation covers feedforward, fully-
connected SNN topologies. The following are known con-
straints:
No convolutional ops.NIR nodes such asnir.Conv2d,
nir.AvgPool2d, andnir.SumPool2doperate on
[channels, height, width]feature maps and have
no equivalent SNN op yet. Supporting them requires new ops
(e.g.,snn.conv2d). The neuron dynamics ops are already
rank-agnostic at the lowering level; extending them toN-D is
straightforward once a convolutional synapse op exists.
Linear-chain graphs only.The Python graph walker fol-
lows a single path from input to output. Branching, residual
connections, and recurrent edges are not supported.
Batch size 1.There is no batched-inference mode. Each call
to the compiled function processes one input sample as it is
intended by NIR standard. The objective are embedded stream
applications rather than batch training acceleration.
Uniform neuron parameters per layer.All neurons in a
layer share the same decay constants and threshold. Per-neuron
parameter arrays are not yet supported.
These constraints are enforced rather than silently assumed.
Each one is surfaced at dialect verification time, so they
manifest as clear diagnostics rather than incorrect output.
VIII. Future Work
Convolutional synapse ops are the most immediate exten-
sions. They would lift the 1-D activation restriction and enable
convolutional SNN topologies common in event-driven vision
and time-series workloads. The neuron dynamics ops already
lowerthroughtype-dispatchandarenotinherentlylimitedto1-
D data; the blocker is the synapse op, not the neuron dynamics.
Residual and recurrent graph support requires extending the
Python graph walker and IR emission layer to handle fan-out
and fan-in edges. The MLIR module format already accom-
modates this naturally (a multi-path network is a function with
additionalmemrefarguments) so the change is concentrated
in the front end. Recurrent graph support, in particular, would
extend snn-mlir to Liquid State Machines, an important class
of reservoir computing SNNs not covered by the current linear-
chain walker.
Neuromorphic hardware backends are a natural next step
once a stable dialect exists. The lowering-pass template estab-
lished bySNNToLinalggeneralizes directly: a new conversion
pass targeting a vendor dialect (e.g., Intel Loihi 2 via Lava,
or SpiNNaker) follows the same one-pattern-per-op structure,
inheriting type-polymorphic dispatch and existing verifiers
for free. We actively welcome open-source contributions of
new backends and hardware architecture targets from the
community.
The most strategically important next step, however, is
coordination with the NIR development team to establish
a standardized quantization and discretization methodology
across the ecosystem. The current scheme (power-of-two
weight quantization, Q12 neuron state, automatic rescaling)
works well in practice, but it is one approach among several
plausible ones. A shared, NIR-level convention for quanti-
zation parameters agreed upon across frameworks and tools
would remove the last remaining per-backend divergence and
make quantized SNN deployment truly interoperable. snn-mlir
iscommittedtocontributingtoandadoptingwhateverstandard
the community converges on.

dependency-free C11 code that runs unchanged on any C-
capable CPU or embedded target. The same IR serves both

当前实现支持前馈式及全连接的 SNN 拓扑结构。以下为已
知约束条件：
无卷积运算。NIR 如 nir 等节点：Conv2d、nir.AvgPool2d 以
及 nir.SumPool2d 均作用于 [通道数，高度，宽度] 的特征图，
目前尚无对应的 SNN 运算。支持这些运算需要引入新的运算
符（例如 snn.conv2d）。神经元动力学运算在降维层面已具
备与维度无关的特性；一旦存在卷积突触运算符，将其扩展
至N维空间便十分简便。
仅支持线性链图。Python Graph Walker 仅沿一条从输入到
输出的单一路径进行遍历；不支持分支结构、残差连接及循

批处理大小为 1。本版本不支持批处理推理模式。每次调
用编译后的函数时，均按 NIR 标准对单个输入样本进行处
理。该功能适用于嵌入式流式应用，而非用于批量训练加
速。
每层神经元参数统一。同一层中的所有神经元共享相同的
衰减常数和阈值。目前不支持按神经元单独设置参数的数组。
这些约束条件并非被默认满足，而是被强制执行。每一条
约束条件均在方言验证阶段显式呈现，因此它们表现为清晰的
诊断信息，而非错误的输出结果。
第八章 未来工作
卷积突触运算符是当前最直接的扩展方案；它们将突破
一维激活限制，从而支持在事件驱动型视觉处理及时间序
列工作负载中常见的卷积 SNN 拓扑结构。神经元动力学
运算符已通过类型调度机制实现降维，且本质上并不局限
于一维数据；限制因素在于突触运算符，而非神经元动力
学本身。
残差与循环图支持需要对 Python 图遍历器及 IR 发射层
进行扩展，以处理扇出与扇入边。 MLIR 模块格式已天然
支 持 这 一 需 求 （ 多 路 径 网 络 实 际 上 是 一 个 带 有 额 外
memref 参数的函数），因此相关改动主要集中在前端部
分。特别是循环图支持，将把 snn-mlir 扩展至“液态状态
机”——这是一类重要的蓄水库计算 SNN 类型，而当前
的线性链式遍历器尚未涵盖此类结构。
在拥有稳定的特定领域语言后，开发神经形态硬件后端
便成为顺理成章的下一步。由SNNToLinalg建立的降级编译
阶段模板可直接推广：针对特定厂商的领域语言（例如通
过 Lava 实现的 Intel Loihi 2 或 SpiNNaker）的新转换编译阶
段，同样遵循“每操作对应一个模式”的结构，从而可无
缝继承类型多态调度机制及现有验证工具。我们热烈欢迎
社区成员为该项目贡献新的后端实现及硬件架构目标。
然而，最具战略意义的下一步是与 NIR 开发团队协调，
在整个生态系统中建立标准化的量化与离散化方法。当前
的方案（2的幂次权重量化、Q12 神经元状态、自动重缩
放）在实践中表现良好，但只是众多可行方案中的一种。
如果能在所有框架和工具中达成一个共享的、 NIR 级别的
量化参数规范，就能消除最后残留的后端差异，使量化后
的 SNN 部署真正实现互操作性。snn-mlir 致力于支持并采
纳社区最终达成的任何标准。
IX. 结论
snn-mlir 首次为脉冲神经网络提供了一个合适的编译器
中间表示。从任何兼容 NIR 的框架中导出的已训练好的
SNN ，会被转换到一种类型多态的 MLIR 方言中；该方言中
的操作具有明确的神经元语义，经过标准 MLIR 基础设施验
证，并通过一次可审计的转换过程，最终生成无依赖关系
的 C11 代码，该代码可在任何支持 C 语言的 CPU 或嵌入式
设备上正常运行且无需修改。同一中间表示既适用于浮点
模拟，也适用于整数部署，前端会自动对齐量化尺度，从
1.34 ×（0.819 → 0.612 毫秒/步），同时将权重数据规模缩减约 4 ×
倍。精度成本较小且取决于具体网络环境：对于 snn_oxford 而言
可忽略不计，对于 snntorch 则较为显著。基于二进制幂次和位移
