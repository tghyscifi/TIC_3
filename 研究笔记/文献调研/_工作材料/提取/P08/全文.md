SNN-MLIR: An MLIR Dialect for Compiling
Neuromorphic SNNs from NIR to Bare-Metal C
Alejandro García Gener ∗, Álvaro Rollón de Pinedo ∗,
Abstract—Spiking neural networks (SNNs) are increasingly
trained in a wide range of frameworks (snnTorch,Lava,Norse,
and others) each with its own model format. The Neuromorphic
Intermediate Representation (NIR) addresses this fragmentation
by providing a common, framework-independent format for ex-
changing trained SNN models. NIR solves the exchange problem,
but it stops there. It provides a description of a network, not
a path to running one. Each backend is still left to implement
deployment on its own, with no shared, transformable compiler
representation in between. This paper presentssnn-mlir, an out-
of-tree MLIR dialect for SNNs together with a NIR→MLIR→C
compilation bridge. The dialect provides a small set of type-
polymorphic operations that work identically on floating-point
(f32/f64) and quantized (i8/i32) data, so a single intermediate
representation serves both simulation and hardware-oriented
deployment. A Python front end reads any NIR file and emits
dialect IR, automatically inserting rescaling operations to keep
quantization scales consistent across layers. A reference lowering
pass converts the dialect to standardlinalgandarithoperations,
from which the toolchain produces self-contained, dependency-
free C11 code that compiles and runs on any C-capable CPU
or embedded target. We evaluate numerical fidelity against
reference outputs, portability across CPU targets, and the cost of
quantization. The current scope is feedforward, fully-connected
networks with a CPU backend.snn-mliris released as open
source under theApache-2.0license with LLVM-exception and
it is already available on Github.

II. Background & related work
A. SNNs and the Cuba-LIF family
Unlike the static, real-valued activations of conventional
artificial neural networks, spiking neural networks compute
over time. A neuron maintains internal state that integrates
incoming signals across discrete timesteps, and it communi-
cates with downstream neurons through spikes (binary, all-or-
nothing events) rather than continuous values. This temporal,
stateful, and largely binary style of computation is what makes
SNNs attractive for low-power hardware: work happens only
when spikes occur, and the data moving between layers are
sparse.
The dominant neuron model in practice is the leaky
integrate-and-fire (LIF) [9] family. A LIF neuron accumulates
input into a membrane potential that decays ("leaks") toward
rest each timestep. When the potential crosses a threshold,
the neuron emits a spike and resets. The current-based variant
(CUBA-LIF) refines this with a second state variable: incom-
ing spikes first charge a synaptic current, which then drives
the membrane voltage, giving the neuron two coupled leaky
states instead of one. Removing the leak (setting the decay
to one) yields the non-leaky integrate-and-fire case (IF), and
removing the threshold yields a pure integrator (I) whose
continuous membrane potential is read out directly (useful
as a final regression or readout layer). These four behaviors
(single versus two-state, and spiking versus integrating) span
the operations our dialect needs to model, and they are exactly
the primitives the NIR standard exposes.
For a compiler audience, the salient point is that these
neurons are not point-wise functions. Each carries state that
must persist across timesteps, a threshold, reset and control
decision, and a sharp distinction between binary spike outputs
and continuous voltage outputs. A representation that flattens
them into anonymous arithmetic loops discards precisely the
structure a compiler would want to reason about.
B. NIR as an exchange format
The Neuromorphic Intermediate Representation addresses
the fragmentation of the SNN ecosystem by defining a
framework-neutral graph format with a fixed vocabulary of
node types (linear and affine synapses, and the LIF/CUBA
neuron family among them). A network trained in one frame-
work can be exported to NIR and read back in another, and
a growing list of simulators (including LAVA, SNNTorch,
Norse, Nengo, Rockpool, and Sinabs [1], [2], [3], [4], [5],
[6]) support it as an export target. By consuming NIR, a
downstream tool inherits all of these frameworks at once,
rather than maintaining an individual importer per framework.
NIR is also deliberately broad in physical scope. It describes
both continuous-time analog and discrete-time digital neuron
models, parameterizing them with continuous quantities such
as membrane and synaptic time constants, leak, and threshold.
This generality is a strength for exchange, but it means a
NIR graph is a mathematical description of a network, not
an executable artifact. NIR fixes the semantics of a model. It
intentionally says nothing about how that model is discretized,
quantized, scheduled, or compiled for a particular target.

C. MLIR and Progressive Lowering
MLIRisacompilerinfrastructureorganizedarounddialects:
Self-contained sets of operations, types, and attributes that
model a particular domain at a particular level of abstrac-
tion. A program is expressed in high-level, domain-specific
dialects and then progressively lowered (through a sequence
of rewrite passes) toward successively lower-level dialects,
until it reaches a form (such as the LLVM dialect) from
which machine code can be generated. Every operation, at
every level, is first-class IR: it can be verified, analyzed, and
transformed by standard passes, and dialects can be mixed
within a single module. This makes MLIR a natural home
for a new domain abstraction. A custom dialect can capture
domain semantics explicitly at the top of the pipeline, then
reuse the entire existing ecosystem of lower-level dialects and
code generators beneath it, rather than building a compiler
stack from scratch.
D. Related Work
Most existing routes from a trained SNN to a deployed one
are framework-specific. A given simulator typically ships its
own deployment or code-generation path, tied to its own model
format and often to a particular hardware target. These paths
work well within their ecosystem but do not compose: a model
must commit to one framework’s toolchain, and porting to
a different target generally means re-exporting, re-quantizing,
and re-implementing the inference loop. NIR removes the
format-level barrier between frameworks, but it stops at the
model boundary, so each backend still re-implements de-
ployment independently—frequently as hand-written inference
loops with target-specific quantization handling.
A second line of work targets neuromorphic hardware
directly, mapping networks onto specific chips through vendor
toolchains. Such compilers are valuable but are, by con-
struction, specialized to their target device and programming
model. What is missing between these two worlds is a shared,
framework-agnostic compiler IR: a representation that is neu-
tral to the source framework, explicit about SNN semantics,
and transformable and retargetable like any other compiler
program. snn-mlir occupies that layer. It takes the framework-
neutral model that NIR provides and gives it a compiler-
neutral intermediate representation in MLIR, one IR that can
be inspected, optimized with standard tooling, and lowered to
a CPU today or to custom hardware tomorrow through the
same backend-extension mechanism.
III. The SNN dialect
The dialect is built on three deliberate choices.
•It is memref-based: Every operand (inputs, weights, neu-
ron state, and outputs) is a memory reference rather than
an SSA value. This matches the reality of the domain,
where neuron state must persist and be updated in place
across timesteps, and it maps cleanly onto the buffers a
C runtime or an embedded target actually allocates.
•The dialect is explicitly typed: Every operation carries
the element type and shape of its operands in the IR text,
so the same operation reads unambiguously whether it is
operating on floating-point or integer data.
•The dialect is designed to be one IR for both simu-
lation and deployment: The same NIR graph serves as
a faithful floating-point reference and as the source for a
quantized, hardware-oriented build; there is no separate
"deployment IR" that can drift out of sync with the
reference.
The guiding idea behind all three is that a spiking network
should be a first-class compiler object. A neuron layer is one
operation that carries its own decay constants and threshold,
not an opaque nest of arithmetic. Standard MLIR passes can
verify it, inspect it, and rewrite it, and the network stays
analyzable and retargetable all the way down.
The dialect defines six operations, covering linear synapses
(with and without bias), rescaling, and the four neuron be-
haviors of the CUBA-LIF family (TABLE I). Each operation
has a human-readable assembly format, so the IR is directly
inspectable and hand-editable. As an example, the CUBA-
LIF neuron layer makes its full structure explicit: The input
current, the two in-place state buffers, the spike output, and
the dynamics parameters as attributes.
The operation reads as exactly what it computes: a 256-
neuron CUBA-LIF layer that decays its synaptic current
and membrane voltage each timestep, fires when the voltage
crosses the threshold, and resets. The state operands are read
and written in place, capturing the temporal nature of the
neuron directly in the IR.

C. MLIR 与渐进式降档
MLIR 是一个基于方言构建的编译器基础设施：每个方
言都是一个自包含的运算、类型和属性集合，用于在特定
抽象层次上对特定领域进行建模。程序以高层、领域特定
的方言编写，随后通过一系列重写遍历逐步降级至更低层
级的方言，直至达到可生成机器码的形式（例如 LLVM 方
言）。在每个抽象层级上，所有运算均为一等中间表示
（IR）：它们均可通过标准遍历进行验证、分析和转换；
且不同方言可在同一个模块内混合使用。这使得 MLIR 成
为引入新领域抽象化的理想平台。自定义方言可在编译流
程的顶层显式捕获领域语义，随后复用其下方所有现有的
低层级方言及代码生成器生态系统，而无需从零开始构建
整个编译器堆栈。
D. 相关工作
目前大多数将训练好的 SNN 模型部署到实际应用中的方
法都具有特定于框架的特性。通常，各类仿真工具都会自
带专属的部署或代码生成路径，这些路径与该工具自身的
模型格式以及特定的硬件目标平台紧密相关。这类路径在
各自的生态系统内运行良好，但无法相互组合：模型必须
绑定到某一框架的工具链上；而要将模型移植到不同的目
标平台，通常意味着需要重新导出、重新量化并重新实现
整个推理循环。 NIR 解除了不同框架之间在格式层面的壁
垒，但其作用仅止于模型层面；因此，每个后端仍需独立
地重新实现部署流程——通常表现为编写针对特定目标平
台进行量化处理的手写推理循环。
第二条研发路线直接针对神经形态硬件，通过厂商提供
的工具链将网络映射到特定芯片上。这类编译器具有重要
价值，但其设计本身便针对特定目标设备和编程模型而定
制。这两个领域之间缺失的，是一种通用且与框架无关的
编译器中间表示（IR）：这种表示法对源框架保持中立，
对 SNN 语义具有明确描述，并且像其他编译器程序一样可
进行转换和重新适配。snn-MLIR 正处于这一层面——它接
收 NIR 提供的、与框架无关的模型，并为其生成一个与编
译器无关的 MLIR 中间表示；该中间表示可被检查、利用标
准工具进行优化，并通过相同的后端扩展机制，无论是在
当前的 CPU 上还是未来的定制硬件上进行代码生成。
III. SNN 方言
该方言的构建基于三个精心设计的选择。
• 该方案基于 memref 架构：每个操作数（输入、权重、神
经元状态及输出）均视为内存引用而非 SSA 值。这与实际
应用场景相符——在该场景中，神经元状态必须持久存在
并在不同时间步长内就地更新；同时，该设计与 C 语言运
行时环境或嵌入式目标平台实际分配的缓冲区完美对应。
• 该方言采用显式类型化机制：每项操作在 IR 文本中
都携带其操作数的元素类型与形状，因此对于同一项
操作而言，无论其作用于浮点数还是整型数据，均可
得到明确无误的识别。
• 该方言旨在为仿真与部署两种场景统一使用一种 IR：
同一个 NIR 图表既可作为精确的浮点数参考基准，也
可作为面向硬件的量化构建的源码；无需存在一个能
够与参考基准脱节的独立“部署 IR”。
这正是本研究所填补的空白。
这三种方法的共同指导思想在于：脉冲网络应被视为一
个一流的编译器对象。神经元层本身就是一个独立的操作
单元，它包含自身的衰减常数和阈值，而非一个不可解析
的算术运算结构；标准的 MLIR 传递机制可对这类网络进行
验证、检查及重写，从而使整个网络在整个处理过程中始
终保持可分析性和可重定向性。

V . Lowering and code generation
The dialect is the top of the pipeline. Everything below it
reuses standard MLIR and LLVM infrastructure. This section
describes the reference lowering from snn ops to standard
dialects, the CPU pipeline that carries it to LLVM IR, and
the C runtime that wraps the result into a self-contained,
dependency-free executable.
The reference lowering,SNNToLinalg, is a conversion pass
that rewrites each snn operation into standardlinalgandarith
operations, the level at which the rest of the MLIR ecosystem
can take over. The pass installs one rewrite pattern per op and
marks the snn dialect illegal, so a successful run leaves no snn
operation behind.
The key point is that the pass dispatches on operand element
type, which is what makes the dialect’s type polymorphism pay
off at the code-generation level. Forsnn.linear, the floating-
point path lowers to alinalg.matvec; the quantized path lowers
to alinalg.genericwhose body sign-extends the i8 operands
and accumulates into the wider i32 output, implementing the
integer matrix-vector product with the correct widening. The
neuron ops lower similarly, expanding their two-line update
(decay, integrate, threshold-and-reset) for spiking neurons;
decay and integrate for integrators intoarithoperations over
the activation vector, and reading the float or int parameter
attributes according to the operand type. Because the float and
integer cases share one op and one pattern, the two code paths
cannot drift apart. They are the same lowering, specialized by
type.
The network itself is emitted as a single MLIR function,
carrying the LLVM attribute. This function advances the
network by exactly one timestep, taking the weight buffers and
the neuron state buffers asmemrefarguments and updating
the state in place. Driving it across time is left to the runtime,
which keeps the compiled kernel small and stateless from the
caller’s point of view. Then, thesnn-opt, the project’s stan-
dalone opt tool, which registers the dialect and the lowering,
appliesSNNToLinalg.
From here, lowering to an executable is a straight, file-free
chain of standard tools. The result is then handed to stock
mlir-opt, which convertslinalgto affine loops, runs standard
cleanup (loop-invariant code motion, CSE, canonicalization),
and lowers progressively through affine, scf, cf and the mem-
ref/arith/func dialects down to the LLVM dialect. Finallymlir-
translateemits textual LLVM IR. From this point, any LLVM-
based compiler produces an object file or executable.
Every stage below snn-opt is an unmodified upstream tool.
The project contributes only the dialect and its one lowering
pass, and inherits the entire optimization and code-generation
stack beneath them.

此在成功运行后，系统中将不再存在任何 SNN 操作。

得该方言在代码生成层面充分发挥了类型多态性优势。对于

路径则会被降级为linalg.generic——其体部分对 i8 类型的操作

而实现了具有正确宽化处理的整数矩阵-向量乘法运算。神经

LLVM 属性。此函数将网络推进恰好一个时间步长，以权重

VII. Limitations
The current implementation covers feedforward, fully-
connected SNN topologies. The following are known con-
straints:
No convolutional ops.NIR nodes such asnir.Conv2d,
nir.AvgPool2d, andnir.SumPool2doperate on
[channels, height, width]feature maps and have
no equivalent SNN op yet. Supporting them requires new ops
(e.g.,snn.conv2d). The neuron dynamics ops are already
rank-agnostic at the lowering level; extending them toN-D is
straightforward once a convolutional synapse op exists.
Linear-chain graphs only.The Python graph walker fol-
lows a single path from input to output. Branching, residual
connections, and recurrent edges are not supported.
Batch size 1.There is no batched-inference mode. Each call
to the compiled function processes one input sample as it is
intended by NIR standard. The objective are embedded stream
applications rather than batch training acceleration.
Uniform neuron parameters per layer.All neurons in a
layer share the same decay constants and threshold. Per-neuron
parameter arrays are not yet supported.
These constraints are enforced rather than silently assumed.
Each one is surfaced at dialect verification time, so they
manifest as clear diagnostics rather than incorrect output.
VIII. Future Work
Convolutional synapse ops are the most immediate exten-
sions. They would lift the 1-D activation restriction and enable
convolutional SNN topologies common in event-driven vision
and time-series workloads. The neuron dynamics ops already
lowerthroughtype-dispatchandarenotinherentlylimitedto1-
D data; the blocker is the synapse op, not the neuron dynamics.
Residual and recurrent graph support requires extending the
Python graph walker and IR emission layer to handle fan-out
and fan-in edges. The MLIR module format already accom-
modates this naturally (a multi-path network is a function with
additionalmemrefarguments) so the change is concentrated
in the front end. Recurrent graph support, in particular, would
extend snn-mlir to Liquid State Machines, an important class
of reservoir computing SNNs not covered by the current linear-
chain walker.
Neuromorphic hardware backends are a natural next step
once a stable dialect exists. The lowering-pass template estab-
lished bySNNToLinalggeneralizes directly: a new conversion
pass targeting a vendor dialect (e.g., Intel Loihi 2 via Lava,
or SpiNNaker) follows the same one-pattern-per-op structure,
inheriting type-polymorphic dispatch and existing verifiers
for free. We actively welcome open-source contributions of
new backends and hardware architecture targets from the
community.
The most strategically important next step, however, is
coordination with the NIR development team to establish
a standardized quantization and discretization methodology
across the ecosystem. The current scheme (power-of-two
weight quantization, Q12 neuron state, automatic rescaling)
works well in practice, but it is one approach among several
plausible ones. A shared, NIR-level convention for quanti-
zation parameters agreed upon across frameworks and tools
would remove the last remaining per-backend divergence and
make quantized SNN deployment truly interoperable. snn-mlir
iscommittedtocontributingtoandadoptingwhateverstandard
the community converges on.
IX. Conclusion
snn-mlir gives spiking neural networks a proper compiler
intermediate representation for the first time. A trained SNN,
exported from any NIR-compatible framework, enters a type-
polymorphic MLIR dialect whose operations carry explicit
neuron semantics, are verified by the standard MLIR in-
frastructure, and lower through a single, auditable pass to
dependency-free C11 code that runs unchanged on any C-
capable CPU or embedded target. The same IR serves both
floating-point simulation and integer deployment, with quanti-

VII. 限制条款
当前实现支持前馈式及全连接的 SNN 拓扑结构。以下为已
知约束条件：
无卷积运算。NIR 如 nir 等节点：Conv2d、nir.AvgPool2d 以
及 nir.SumPool2d 均作用于 [通道数，高度，宽度] 的特征图，
目前尚无对应的 SNN 运算。支持这些运算需要引入新的运算
符（例如 snn.conv2d）。神经元动力学运算在降维层面已具
备与维度无关的特性；一旦存在卷积突触运算符，将其扩展
至N维空间便十分简便。
仅支持线性链图。Python Graph Walker 仅沿一条从输入到
输出的单一路径进行遍历；不支持分支结构、残差连接及循
环边。
批处理大小为 1。本版本不支持批处理推理模式。每次调
用编译后的函数时，均按 NIR 标准对单个输入样本进行处
理。该功能适用于嵌入式流式应用，而非用于批量训练加
速。
每层神经元参数统一。同一层中的所有神经元共享相同的
衰减常数和阈值。目前不支持按神经元单独设置参数的数组。
这些约束条件并非被默认满足，而是被强制执行。每一条
约束条件均在方言验证阶段显式呈现，因此它们表现为清晰的
诊断信息，而非错误的输出结果。
第八章 未来工作
卷积突触运算符是当前最直接的扩展方案；它们将突破
一维激活限制，从而支持在事件驱动型视觉处理及时间序
列工作负载中常见的卷积 SNN 拓扑结构。神经元动力学
运算符已通过类型调度机制实现降维，且本质上并不局限
于一维数据；限制因素在于突触运算符，而非神经元动力
学本身。
残差与循环图支持需要对 Python 图遍历器及 IR 发射层
进行扩展，以处理扇出与扇入边。 MLIR 模块格式已天然
支 持 这 一 需 求 （ 多 路 径 网 络 实 际 上 是 一 个 带 有 额 外
memref 参数的函数），因此相关改动主要集中在前端部
分。特别是循环图支持，将把 snn-mlir 扩展至“液态状态
机”——这是一类重要的蓄水库计算 SNN 类型，而当前
的线性链式遍历器尚未涵盖此类结构。
在拥有稳定的特定领域语言后，开发神经形态硬件后端
便成为顺理成章的下一步。由SNNToLinalg建立的降级编译
阶段模板可直接推广：针对特定厂商的领域语言（例如通
过 Lava 实现的 Intel Loihi 2 或 SpiNNaker）的新转换编译阶
段，同样遵循“每操作对应一个模式”的结构，从而可无
缝继承类型多态调度机制及现有验证工具。我们热烈欢迎
社区成员为该项目贡献新的后端实现及硬件架构目标。
然而，最具战略意义的下一步是与 NIR 开发团队协调，
在整个生态系统中建立标准化的量化与离散化方法。当前
的方案（2的幂次权重量化、Q12 神经元状态、自动重缩
放）在实践中表现良好，但只是众多可行方案中的一种。
如果能在所有框架和工具中达成一个共享的、 NIR 级别的
量化参数规范，就能消除最后残留的后端差异，使量化后
的 SNN 部署真正实现互操作性。snn-mlir 致力于支持并采
纳社区最终达成的任何标准。
IX. 结论
snn-mlir 首次为脉冲神经网络提供了一个合适的编译器
中间表示。从任何兼容 NIR 的框架中导出的已训练好的
SNN ，会被转换到一种类型多态的 MLIR 方言中；该方言中
的操作具有明确的神经元语义，经过标准 MLIR 基础设施验
证，并通过一次可审计的转换过程，最终生成无依赖关系
的 C11 代码，该代码可在任何支持 C 语言的 CPU 或嵌入式
设备上正常运行且无需修改。同一中间表示既适用于浮点
模拟，也适用于整数部署，前端会自动对齐量化尺度，从
1.34 ×（0.819 → 0.612 毫秒/步），同时将权重数据规模缩减约 4 ×
倍。精度成本较小且取决于具体网络环境：对于 snn_oxford 而言
可忽略不计，对于 snntorch 则较为显著。基于二进制幂次和位移
的方案使这些性能提升基本无需承担算术运算开销。每次尺寸调整
仅涉及单次位移操作，而非乘除运算；这也使得整数版本的实现足
够确定性，在 x86 与 RISC-V 平台上具有完全相同的位级行为。
