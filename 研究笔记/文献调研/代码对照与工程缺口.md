# 代码对照与工程缺口

本笔记只记录本地源码的静态核验；没有执行模型推理、编译、行为仿真或上板实验。问题分为“源码已确认”和“尚需最小复现实验的风险”，不能把后者当成已观测失败。源码缺口也不等于学术创新。

## 1. 当前前后端的真实边界

[`onnx2map.py`](../../onnx2map.py) 第 24—37 行导入 `onnx2prim` 的 parser、address_allocator、codegen、hardware_config 和 memory_planner。当前工作树没有提供这组实现，因此入口文件不是一个已经可运行的完整编译器。

第 87 行起的生成函数使用 `LayerSeq`、stage 划分、地址分配、生成 Python 源码和 `exec` 组合流程。这些接口是兼容现有工程的约束，但不是所有新 IR 都必须沿用的语义设计。保留一个兼容适配层，比让层序列承担循环、分支和神经元状态更合适。

[`onnx_to_lenet_py_README.md`](../../onnx_to_lenet_py_README.md) 的限制说明：当前生成路径面向线性 Conv / MaxPool / FC 拓扑。不能从 ANN LeNet 成功就推导出 ONNX 中任意 SNN 时间展开、控制流、共享状态均受支持。

## 2. 已确认的实现事实

| 位置 | 源码事实 | 对课题的影响 |
|---|---|---|
| `onnx2map.py:64` | checkpoint 导入使用 `strict=False`；只识别部分包装方式 | 静默缺失参数是错误来源；导入报告应列出缺失/多余键和形状，而不是默认视为模型已加载 |
| `onnx2map.py:123,181,186` | 单组路径的输入组、计算组、输出组都传 `core_offset=(0,0)` | 需要检查不同组在同一物理核的配置是否冲突，不能仅用阶段数量判断合法性 |
| `onnx2map.py:163` | 多组路径产生 `top_code`，随后并未执行或保存它 | 生成 top 源码不意味着最终返回配置包含它的调度逻辑 |
| `onnx2map.py:229` | 对原始 `mcfg` 调用 `json.dump` | 原始 dict 的 tuple 键和 Primitive 对象不是标准 JSON；必须走正式硬件序列化层，而非把 Python IR 直接 dump |
| `onnx_to_lenet_py.py:216` | cut/weight 参数由层大小启发式推算 | 这不是使用激活分布的校准；层大小不能单独确定溢出率或分类精度 |
| `onnx_to_lenet_py.py:617` | 生成的比较器 `add_ref_data/run/show_result` 都是 `pass` | “调用了 check”不能作为数值结果被验证的证据 |
| `map_config_gen.py:376,380` | `check` 和 `_check_static_prim_end_addr` 是空实现 | 需要新静态验证器；但工厂内部已有零散断言，不能说整个包完全没有任何检查 |
| `test_engine.py:39` | 非 Windows 平台运行 Python 仿真后直接返回 `True` | 返回 True 在不同平台代表不同验证等级，评测必须显式报告跑过哪些后端 |
| `test_engine.py:95` 起 | `cmp_out` 文件名筛选取 `name_prefix[3]`，并分别构造 group/phase 集合 | 按文件名 `cmp_out_chipx_chipy_group_corex_corey`，索引 3 实际为 chipy；独立集合也会扩大 group-phase 配对。覆盖率必须另行检查 |

后两项尤其重要：两个仿真器输出相同，只能证明它们对所比较配置的一致性，不能证明导出的源模型和量化模型之间的等价性，更不能证明没有漏比较文件。

## 3. p08 不只是“LIF”这个标签

[`primitive/Prim_08_lif_new.py`](../../primitive/Prim_08_lif_new.py) 第 287 行起的行为实现明确规定：

1. 读取/恢复膜电位、不应期、自适应阈值等状态；生成随机阈值项。
2. 仅不应期计数为 0 的神经元累加输入，膜电位进行 28 位饱和。
3. 使用严格比较 `V > Vth` 得到 spike，而不是默认 `>=`。
4. 按 `Rst_mode` 进行固定电位复位、减阈值或减固定量。
5. **复位之后**进行泄漏；自适应泄漏为整数 `V_update * alpha // 256 + beta`。
6. 再更新自适应阈值、不应期和时间窗，并把新状态写回。
7. `fire_type` 选择 spike 或电位等不同输出，输出通道的填充规则也依模式变化。

上述是软件行为模型的实际语义，硬件设计是否逐项对应，需要与 P07 对照。一个框架中的同名 LIF 如果采用“先泄漏后积分”“先检查后积分”或不同阈值比较，不能只改参数就宣布等价。

第 315 行附近 `self.Vth.clip(...)` 没有接回返回值，是值得单独测试的代码风险；尚未进行异常阈值测试，不据此声称现有模型结果错误。

另一个更直接的状态风险是第 290 行 `Tw_finish = Tw_cnt >= Tw_len` 没有检查 `Tw_en`，后续会据此将 `V_new` 复位为 `Vinit`。而工厂默认参数为 `Tw_en=False, Tw_cnt=0, Tw_len=0`。从静态控制流看，这组默认值不能直接假定具有跨时间步累积膜电位的行为；需对照硬件规格，并做“关闭时间窗、连续亚阈值输入”的最小测试。该风险还没有通过实际运行确认，不应在正式评测前把现有 p08 当成无误差的参考真值。

## 4. 必须一起描述的四类 IR 信息

建议图节点之外显式保存以下信息；这是本次源码核验的设计推断，不是已有模块功能：

- 算术：输入/权重/累加/输出 dtype、scale、截断位置、饱和和比较规则。
- 状态：状态变量形状、初值、写回位置、跨时间步生命周期、跨样本复位边界。
- 时间：模型时间步、状态更新依赖、phase 顺序、step 循环和物理时钟预算之间的映射。
- 物理：tensor 逻辑布局与芯片填充/打包布局、bank、地址单位、路由包长度与目标核。

[`DataHandler.tensor_split`](../../generator/mapping_utils/data_handler.py) 第 19 行起提供数据打包，但并不是内存生命周期分析或布局正确性的证明。一个总容量阈值，也不能替代不同 memory bank 的合法访问范围和状态存储约束。

地址单位必须跟踪整条链：LeNet 在传入 Primitive 之前将字节常量 `>>2`，行为存储以 4 字节 word 为项；`primitive_json.py` 部分寄存器字段仍再右移 2 或 1。这是上层 word 到不同硬件访问粒度的编码，不能看到第二次右移就误判“工厂接收字节地址”。主线程已据行为存储和 int32 长度修正 E01 的这一条初始推断，具体字段仍需逐项核验。

## 5. 验证路线建议

先建立浮点源模型、明确离散化的整数参考模型、原语行为模型三层关系，再增加 `TianjicX1_SIM.exe` 和实际硬件。源码 [`hardwar_proxy.py:14`](../../generator/test_engine/hardwar_proxy.py) 的注释称其为 C++ 仿真器；目前没有核实它是 RTL/Verilog 仿真，应使用“X1 可执行仿真器”的中性名称。

对每个模型保存：所有权重和状态的导入报告、每层/每时间步张量比较、布局 round-trip、原语参数合法性、内存读写与活跃区间、实际比较文件列表、执行后端和版本。地址和原语序列逐项一致适合最初回归，但优化后应以语义输出一致为主，不能要求所有合法优化仍复刻手写地址。

## 6. 候选回归模型的入口审计

以下都是静态线索，未执行脚本，不把历史手写示例直接认定为可信多步 SNN 基线：

- `generator/full.py:107` 的数据采集只调用 `num_steps=1`；即使模型类默认 25 步，一步中间张量也不足以验证 25 步状态递推。
- `generator/full.py:48` 的 FC 输入为 `32*7*7`；使用训练得到的 checkpoint 前要逐层核对形状、结构和预处理，路径存在不代表相容。
- `generator/shd/shd_top.py:9` 起仍引用 `generator.zhl_nmi22.shd` 旧路径；SHD 适合 FC-SNN 研究，但“结构合适”不代表当前脚本可直接运行。
- `generator/snnlenet/snnlenet.py:251` 起使用硬编码 checkpoint 路径，缺失时改用随机初始化；若不记录此分支，很容易把随机模型映射成功误当训练模型部署正确。

先审计模型/权重/状态/输入协议，再用它作为性能或精度基线。本次没有修复这些入口，也没有启动会清理历史输出的 TestEngine。
