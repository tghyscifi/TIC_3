# 第二阶段：接口与语义审查

执行者：主代理；子代理分别实现解析器、布局/地址模块和计算后端，主代理负责集成、审查、量化、参考执行及验收。

## 审查结论

该原型可以进入“人工精修”的阶段，但范围限定为 ANN 单核计算。SNN 与全芯片自动映射没有完成。当前保留原项目低层实现，不进行替换；生成器在无法证明正确的路径上报错。

## 已固定的契约

| 问题 | 决定 | 验证证据 |
|---|---|---|
| 宽高顺序 | px/kx/sx 为宽，py/ky/sy 为高；逻辑形状 CHW | parser 与非正方形计算测试 |
| 地址单位 | allocator 与 primitive 使用 4-byte word；编码到 JSON 时由原 serializer 处理字段粒度 | 对齐/bank 校验与 JSON 序列化测试 |
| 逻辑尺寸与填充尺寸 | int8 激活通道补到 16，权重输出通道补到 32；p81 输入按宽补 16 | packing roundtrip、物理 FC 点积测试 |
| 展平布局 | 源模型 CHW/HWC 显式记录；CHW FC 权重在打包时重排列 | 非正方形 signed Conv→FC 数值闭环 |
| 池化与截断 | 只融合已确认的无 padding 2×2 stride2；其最大值与单调标量 Cut/ReLU 可交换 | 五阶段 LeNet 对照与逐元素比较 |
| 卷积临时空间 | 融合池化用两行 INT32 scratch，不按完整卷积结果错误占满 Mem0 | allocator footprint 检查、原 Memory 执行 |
| 地址复用 | 新 allocator 暂不复用激活，只共享跨阶段 scratch；权重/偏置常驻 | overlap/bankspill/out-of-space 测试 |
| 量化 | 显式配置、拒绝隐式猜测与静默裁剪；参考与目标均执行同一整数模型 | Cut 负数取整、范围、溢出拒绝测试 |
| 状态模型 | StateSpec/TimeContract 是接口，不是已支持的 LIF 执行；有状态模型被拒绝 | state-not-dropped 测试 |

## 集成时发现并修复的问题

1. 直接创建 Soma 对象后，其派生输出长度尚未初始化。原系统由 PIGroup 调用 `cal_para()`；新 builder 补齐同样的准备步骤后再执行原语。
2. 初稿生成入口只会抛异常，不能作为可执行原型。现在的 `generate_g1_1core` 会生成实际 compute adapter；routing 仍明确拒绝。
3. 初稿只检查地址区间，未检查调用方提供的 footprint 是否与补齐布局一致。现在同时验证五类物理长度，不能通过缩短长度隐藏越界。
4. FC 的 row-check 字段初稿与手写 LeNet 不同。已按手写单行配置调整为 `Row_ck_on=1, in_row_max=1`，并纳入字段对照。
5. 临时目录默认落在受限的 Windows sandbox Temp，集成测试改用项目专属临时目录；测试清理仅针对自身新建目录，不触碰已有仿真输出。

## 验收证据

2026-10-12 最终回归：30 项 unittest 全部通过；CLI 使用 `--verify` 成功生成 `prototype_runs/lenet_run_002` 的八个输出文件；新 package、测试和示例的 compileall 通过。

`tests/prototype/test_pipeline.py` 既运行自动分配地址的 LeNet，也调用原 `generator/LeNet/g1_1core.py` 构造手写计算阶段，使用同一确定性参数输入，逐阶段对照独立整数 oracle。计算 primitive 类型、宽高/核/步长、通道、Cut、比较常数、地址 reset、row-check 等字段有直接比较；自动与手写的激活地址不同，这是 allocator 策略差异，不要求字典完全相同。

另有非正方形、有负激活、CHW 展平 FC 的行为测试，防止仅方形 LeNet 或全零结果掩盖轴顺序问题。导出的 mapping.py 会重新执行编译并再次验证；JSON 检查包含六个 PI 槽位阶段。

复现方式与完整输出文件说明见 `../README.md`。测试通过不意味着覆盖所有字段位宽、router header、静态 PI 空间或时钟约束。

## 尚需人工精修的内容

- 导入实际训练 checkpoint，确认模型拓扑与权重完全匹配；当前 fixture 是合成参数。
- 制定和验证量化策略，包括输入尺度、每层权重/偏置尺度与 Cut；不能只优化编译输出一致性而忽略任务精度。
- 完整的芯片约束 validator，包括原语字段编码范围、静态 PI/RHead、输入布局切换和路由/时钟资源。当前 validator 只是严格的单核数据 SRAM 子集。
- 激活 lifetime 复用、通道 padding 后的 Flatten 压紧、更宽的空间算子和整核输入方式。
- 根据已确认的状态转移，设计并测试 LIF 微型轨迹：阈值边界、漏电舍入、复位顺序、时间窗、sample/step 状态重置。
- 恢复完整 G0/G1/G2 网络并独立验证路由与 timing，再调用外部 exe 或芯片。

## 不应被误读的结果

导出的 `hardware_config.json` 经过原序列化器，并不意味着已被外部硬件模拟器接受。`verify_behavior()` 验证的是原项目计算原语与 Memory 行为，未执行整个 ChipArray、路由仲裁或周期同步。现阶段不报告芯片精度、吞吐、功耗，也不报告 SNN 编译成功。
